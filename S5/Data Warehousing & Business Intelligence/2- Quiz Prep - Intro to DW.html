1Chapter 1: The Compelling Need for Data Warehousing

Detailed notes on the Information Crisis, Past Failures, and the need for Strategic Information.

We are drowning in data but have little knowledge. This is the Information Crisis. Companies have accumulated mountains of data over decades, but this data is siloed in operational systems and cannot be readily used to make strategic decisions.

The Need for Strategic Information

Executives need strategic information to gain a competitive edge, improve performance, and steer the company in the proper direction. Strategic information must have 5 characteristics:

  • Integrated: A single, enterprise-wide view.
  • Data Integrity: Accurate and conforms to business rules.
  • Accessible: Responsive for analysis with intuitive access paths.
  • Credible: Trusted by users; every business factor has one and only one value.
  • Timely: Available within the stipulated time frame.
Definition
Strategic Information vs. Operational Data: Operational data is event-driven and provides snapshots of transactions. Strategic information is broad-based, integrated, and used to spot trends over time (e.g., tracking customer loyalty or evaluating route profitability).

Failures of Past Decision-Support Systems

Before Data Warehousing, IT departments tried to provide strategic information using several inadequate methods. These attempts failed because they relied on operational systems that were never designed for analysis:

  • Ad hoc Reports: Custom programs written for each request. Overwhelmed IT.
  • Special Extract Programs: Suites of programs run periodically to extract data into files.
  • Small Applications & Information Centers: Pre-determined reports/screens. Too rigid.
  • Executive Information Systems (EIS): Preprogrammed screens for executives. They lacked the flexibility to drill down into the data when new questions arose.
Common Mistake
The Familiar Merry-Go-Round: Users request a report -> IT places request on backlog -> 4 to 6 weeks pass -> IT delivers report -> User discovers they need different data -> User requests a new report. The cycle repeats endlessly.

Evolution of Business Intelligence (BI)

Business Intelligence (BI) is the umbrella term for applications and technologies that gather, cleanse, and analyze data to improve decision-making. It consists of two environments:

  • Data to Information (The DW): Extracting, cleansing, transforming, and storing data.
  • Information to Knowledge (Analytics): Analytical tools used by users to access and analyze the stored data.

Key Takeaways

  • Operational (OLTP) systems run the business; Informational (DW/DSS) systems watch and analyze the business.
  • Past attempts failed because they tried to pull strategic insights directly from highly normalized, siloed operational databases.
  • A Data Warehouse is the only viable solution because it provides an environment explicitly designed for read-intensive, interactive, historical analysis.

2Chapter 2: Data Warehouse Building Blocks

Detailed notes on defining features, architectures, and the five core components.

Defining Features of a Data Warehouse

Bill Inmon (the father of DW) and Sean Kelly defined the core characteristics of a data warehouse. It must be:

  • Subject-Oriented: Data is stored by real-world business subjects (e.g., Customer, Product, Sales) rather than by applications (e.g., Order Processing, Billing).
  • Integrated: Data from diverse sources is standardized. Inconsistencies in naming conventions, codes, and measurements are removed.
  • Time-Variant: Data is kept as historical snapshots. Every record contains a time element, allowing for historical trend analysis.
  • Nonvolatile: Data is read-only. It is loaded in batches and is not updated in real-time by individual transactions.
Example

Data Granularity

Data granularity refers to the level of detail. A bank might keep three levels of granularity in its DW: Daily Detail: Individual deposit/withdrawal amounts. Monthly Summary: Number of transactions and ending balance per month. Quarterly Summary: Number of transactions and ending balance per quarter.

Data Warehouses vs. Data Marts

A Data Mart is a subset of the DW targeted to a specific business group (e.g., Sales Data Mart). The two leading approaches to building the architecture are:

ApproachDescriptionPros & Cons
Top-Down (Inmon CIF) Build a centralized, enterprise-wide DW (in 3NF) first. Then, create dependent data marts (Hub-and-Spoke). Pros: True corporate view, centralized control. Cons: Takes years to build, high risk of failure.
Bottom-Up (Kimball Bus) Build iterative data marts one by one. Link them together using conformed dimensions to form the enterprise DW (Data-Mart Bus). Pros: Faster ROI, manageable pieces. Cons: Requires strict discipline to avoid creating independent, fragmented data silos.
Pro Tip
Independent Data Marts (built directly from operational sources without a central strategy) are considered an architectural failure because they perpetuate data redundancy and inconsistent numbers across departments.

The 5 Building Blocks of DW Architecture

  1. Source Data: Includes Production Data (OLTP databases with high disparity), Internal Data (spreadsheets, docs), Archived Data (historical backups), and External Data (purchased industry benchmarks).
  2. Data Staging (ETL): The workbench where data is Extracted, Transformed (cleaned, standardized, aggregated, surrogate keys assigned), and Loaded. Must be physically separate from the source and the target DW.
  3. Data Storage: The actual repository (RDBMS or MDDBMS) optimized for read-heavy, analytical queries.
  4. Information Delivery: The tools used by users to consume data (Ad hoc reports, OLAP/Complex queries, Data Mining, Dashboards).
  5. Management and Control: Coordinates ETL scheduling, user access, and interacts with Metadata to orchestrate the whole system.
Definition
Metadata: "Data about data." It acts as the glue of the DW.
Operational Metadata: Info about source system structures.
Extraction/Transformation Metadata: Info about ETL rules and mappings.
End-User Metadata: The business dictionary that helps users navigate the DW.

3Chapter 1 & 2 Review Questions

Proper quiz prep covering the end-of-chapter questions from the textbook.

Q1: Why were past attempts by IT to provide strategic information failures? List three concrete reasons.

Answer: 1. Attempting to use Operational Data directly: They tried to query OLTP systems which were event-driven, highly normalized, and lacked historical depth.
2. The "Merry-Go-Round" effect: Lack of self-service. Users requested an ad-hoc report, waited weeks, then realized they needed slightly different data, overwhelming IT.
3. Data Fragmentation: Extract programs pulled from disparate systems without integrating or cleaning the data, leading to inconsistent and non-credible reports.

Q2: Describe five differences between operational systems and informational systems.

Answer: 1. Content: Operational has current values; Informational has archived, derived, and summarized data.
2. Structure: Operational is optimized for transactions (normalized); Informational is optimized for queries (denormalized).
3. Usage: Operational is predictable and repetitive; Informational is ad-hoc, random, and heuristic.
4. Access Type: Operational involves read, update, delete; Informational is read-only.
5. Users: Operational is used by a large number of front-line staff; Informational is used by a relatively smaller number of analysts and executives.

Q3: Explain the 4 defining features of a Data Warehouse.

Answer: 1. Subject-Oriented: Data is grouped by business entities (Customers, Sales) rather than by applications (Order Entry).
2. Integrated: Data from disparate sources is unified, standardizing naming conventions, measurements, and formats.
3. Time-Variant: Data is stored as a series of snapshots over time, rather than just keeping the most current value.
4. Nonvolatile: Data is loaded periodically in batches and is not updated in real-time. It is read-only.

Q4: How do Top-Down and Bottom-Up approaches differ?

Answer: Top-Down (Inmon): Builds the massive, enterprise-wide DW first, then feeds dependent data marts from it. High consistency, but takes a very long time to build.
Bottom-Up (Kimball): Builds departmental data marts one at a time to show quick ROI. As long as these marts share "conformed dimensions," they logically link together to form the enterprise DW.

Q5: Why do you need a separate Data Staging component?

Answer: Data Staging must be separate because extracting, cleaning, transforming, and deduplicating data from multiple disparate sources is computationally heavy. If you did this in the source system, you would degrade operational performance. If you did it directly in the DW, you would expose users to dirty, inconsistent data during the transformation process. It acts as a safe "prep kitchen."

Q6: What are the three major types of metadata in a data warehouse?

Answer: 1. Operational Metadata: Defines the source systems and their data structures.
2. Extraction and Transformation Metadata: Documents the ETL rules, mappings, and load schedules.
3. End-User Metadata: Provides a business glossary and navigation map so users can query the data using familiar business terms.

Multiple Choice

1. According to Amdahl's Law, what primarily limits the speedup you can get by adding more parallel processors?

Answer: B
A) The speed of the hard drives
B) The fraction of the program that must be executed sequentially
C) The amount of RAM available
D) Network bandwidth
Explanation: SpeedUp = 1 / (Sequential Fraction + (Parallel Fraction / Processors)). The sequential fraction acts as a hard ceiling.

2. An architecture where independent data marts are built directly from operational sources without conforming dimensions usually results in:

Answer: A
A) Fragmented data silos and inconsistent reporting across the enterprise
B) A perfectly integrated enterprise data warehouse
C) The Inmon Corporate Information Factory
D) High credibility among executives
Explanation: Independent data marts are an anti-pattern. Because they do not share conformed dimensions or a central DW, they produce conflicting data.

3. Which component of the DW architecture is responsible for interacting with Metadata to orchestrate ETL schedules and user access?

Answer: C
A) Information Delivery
B) Data Storage
C) Management & Control
D) Data Staging

Final Quiz Tips

  • Top-down = Inmon = Centralized DW first, dependent marts later.
  • Bottom-up = Kimball = Data Mart Bus, conformed dimensions.
  • Operational (OLTP) = Runs the business, current data, high transactions.
  • Informational (DSS/DW) = Watches the business, historical data, read-only.
  • Metadata = Data about data, essential for credibility and orchestration.
