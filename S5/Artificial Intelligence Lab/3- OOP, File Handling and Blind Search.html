Lab 4 — OOP, File Handling and Blind Search Algorithms

1OOP and Inheritance

Classes, objects, methods — how to model real-world things in code

OOP (Object-Oriented Programming) lets you bundle data (attributes) and behaviour (methods) into one unit called a class. Create multiple objects from the same blueprint. Inheritance lets a subclass reuse and extend a parent class.

class Vehicle:
school_name = "ABC" # ← class variable (shared by ALL objects)
def __init__(self, brand, speed): # ← constructor
self.brand = brand # ← instance variable (unique per object)
self.speed = speed
def move(self): # ← instance method
print(f"{self.brand} moving at {self.speed}")
@classmethod
def change_name(cls, name): cls.school_name = name # ← class method
@staticmethod
def validate_speed(s): return s > 0 # ← static method
Example

Full OOP Hierarchy — Vehicle → Car → ElectricCar

# ── BASE CLASS ───────────────────────────────────────
class Vehicle:
    school_name = "FAST"   # class variable — shared by all

    def __init__(self, brand, speed):
        self.brand = brand    # instance variable — unique per object
        self.speed = speed

    def move(self):
        print(f"{self.brand} is moving at {self.speed} km/h")

    @classmethod
    def change_school(cls, name):   # modifies class variable
        cls.school_name = name

    @staticmethod
    def validate_speed(s):          # no access to self or cls
        return s > 0


# ── SINGLE INHERITANCE ────────────────────────────────
class Car(Vehicle):
    def __init__(self, brand, speed, num_doors):
        super().__init__(brand, speed)   # call parent constructor
        self.num_doors = num_doors

    def honk(self):
        print(f"{self.brand} goes BEEP! ({self.num_doors} doors)")


# ── ANOTHER DERIVED CLASS ─────────────────────────────
class Bike(Vehicle):
    def __init__(self, brand, speed, engine_capacity):
        super().__init__(brand, speed)
        self.engine_capacity = engine_capacity

    def rev(self):
        print(f"{self.brand} VROOOOM! {self.engine_capacity}cc")


# ── MULTILEVEL INHERITANCE ────────────────────────────
class ElectricCar(Car):   # ElectricCar → Car → Vehicle
    def __init__(self, brand, speed, num_doors, battery):
        super().__init__(brand, speed, num_doors)  # calls Car.__init__
        self.battery = battery

    def charge(self):
        print(f"Charging {self.brand} ({self.battery}kWh battery)")


# ── USAGE ─────────────────────────────────────────────
v = Vehicle("Generic", 100)
v.move()           # Generic is moving at 100 km/h

c = Car("Toyota", 120, 4)
c.move()           # inherited from Vehicle
c.honk()           # own method

b = Bike("Yamaha", 80, 150)
b.rev()

ec = ElectricCar("Tesla", 200, 4, 75)
ec.move()          # from Vehicle (via Car)
ec.honk()          # from Car
ec.charge()        # own

# Class method and static method
Vehicle.change_school("MIT")
print(Vehicle.school_name)  # "MIT"
print(Vehicle.validate_speed(50))  # True
Definition
super(): Refers to the parent class. super().__init__(...) calls the parent's constructor, allowing the child to initialize inherited attributes without duplicating code. Always call super().__init__ in child constructors!
Exam Hint
Know the difference: Instance method takes self — accesses object data. Class method (@classmethod) takes cls — accesses class data. Static method (@staticmethod) takes neither — a utility function that happens to live in the class.
Common Mistake
Forgetting self. before instance variables. brand = "Toyota" inside __init__ creates a LOCAL variable that disappears. self.brand = "Toyota" creates an INSTANCE variable that persists.

Key Takeaways

  • Class variable: shared across all instances — defined outside __init__
  • Instance variable: unique per object — defined with self.x = ... in __init__
  • Inheritance: class Child(Parent) — child inherits all parent methods
  • super().__init__(...) calls parent constructor — always do this
  • Multilevel: A → B → C — each calls super() to chain up

Example

The Building Blocks — Copy These Into Every Search Program

# ── NODE CLASS (used by ALL search algorithms) ────────
class Node:
    def __init__(self, state, parent=None, cost=0, depth=0):
        self.state = state
        self.parent = parent
        self.cost = cost
        self.depth = depth

    # Required for heapq to compare nodes (UCS uses priority queue)
    def __lt__(self, other):
        return self.cost < other.cost


# ── PATH RECONSTRUCTION ──────────────────────────────
# When goal is found, trace back through parent pointers
def get_path(node):
    path = []
    while node:
        path.append(node.state)
        node = node.parent
    return path[::-1]   # reverse: start → goal


# ── GRAPH REPRESENTATIONS ─────────────────────────────
# Unweighted graph (for BFS, DFS, IDS)
graph = {
    'A': ['B', 'C'],
    'B': ['D', 'E'],
    'C': ['F'],
    'D': [],
    'E': [],
    'F': []
}

# Weighted graph (for UCS, Greedy, A*)
weighted_graph = {
    'A': [('B', 1), ('C', 4)],
    'B': [('D', 2)],
    'C': [('D', 1)],

# ── EXAMPLE USAGE ─────────────────────────────────────
root = Node('A')
child_b = Node('B', parent=root, cost=1, depth=1)
child_d = Node('D', parent=child_b, cost=3, depth=2)

print(get_path(child_d))  # ['A', 'B', 'D']
Definition
State Space: The collection of all possible states of a problem and the transitions between them. Represented as a graph where nodes = states, edges = actions.

Uninformed (Blind) Search: Algorithms that search without any knowledge of how far they are from the goal. They only know: start state, goal state, and available actions. No heuristic.

Key Takeaways

  • Every search algorithm uses a Node class: state, parent, cost, depth
  • Path reconstruction: follow parent pointers from goal back to start, then reverse
  • Unweighted graph: {'A': ['B','C']} | Weighted: {'A': [('B',1),('C',4)]}
  • Track visited states with a visited = set() to avoid infinite loops
  • The key differences between algorithms are the data structure used (queue vs stack vs priority queue)

3BFS — Breadth First Search

Explores level by level — finds the shortest path in unweighted graphs

BFS is like ripples in a pond — it explores all nodes at distance 1 first, then all at distance 2, etc. It uses a Queue (FIFO) — "First In, First Out" — which is what makes it explore level by level.

BFS exploration order on example graph
A ← Start (Level 0)
↓
B C ← Level 1
↓
D E F ← Level 2
Order: A → B → C → D → E → F
Example

BFS Implementation

from collections import deque

graph = {
    'A': ['B', 'C'],
    'B': ['D', 'E'],
    'C': ['F'],
    'D': [], 'E': [], 'F': []
}

class Node:
    def __init__(self, state, parent=None, cost=0, depth=0):
        self.state = state; self.parent = parent
        self.cost = cost; self.depth = depth

def get_path(node):
    path = []
    while node:
        path.append(node.state); node = node.parent
    return path[::-1]

def bfs(graph, start, goal):
    queue = deque([Node(start)])   # FIFO queue
    visited = set()

    while queue:
        current = queue.popleft()  # remove from FRONT
        state = current.state

        if state == goal:
            return get_path(current)

        if state in visited:
            continue
        visited.add(state)

        for neighbor in graph[state]:
            if neighbor not in visited:
                child = Node(neighbor, parent=current,
                             depth=current.depth + 1)
                queue.append(child)  # add to BACK

    return None   # no path found

path = bfs(graph, 'A', 'F')
print("BFS Path:", path)   # ['A', 'C', 'F']
Definition
Queue (FIFO): First In, First Out. deque.popleft() removes from front. New nodes are added to the back. This guarantees level-by-level exploration = shortest path (unweighted).
Pro Tip
Use from collections import deque for BFS — it's O(1) for popleft(). Never use a regular list for BFS because list.pop(0) is O(n) (slow — shifts all elements).

BFS Properties

  • Data Structure: Queue (FIFO) — deque
  • Optimal: Yes — finds shortest path in unweighted graphs
  • Complete: Yes — always finds a solution if one exists
  • Memory: High — stores all nodes at current level
  • Add: queue.append() to back | Remove: queue.popleft() from front

4DFS — Depth First Search

Explores as deep as possible — memory efficient but may get lost in infinite depth

DFS is like exploring a maze by always taking the first new path you see, going as deep as possible before backtracking. It uses a Stack (LIFO) — "Last In, First Out" — which gives the deep-first behaviour.

Queue (BFS) — FIFO
[A, B, C] → pop left → A
[B, C] → pop left → B
[C, D, E] → pop left → C
Level-by-level
Stack (DFS) — LIFO
[A] → pop → A
[B, C] → pop → C
[B, F] → pop → F
Deep-first
Example

DFS Implementation

def dfs(graph, start, goal):
    stack = [Node(start)]   # LIFO stack (regular list)
    visited = set()

    while stack:
        current = stack.pop()   # remove from TOP (last item)
        state = current.state

        if state == goal:
            return get_path(current)

        if state in visited:
            continue
        visited.add(state)

        # Add neighbors to stack — they'll be explored next
        for neighbor in graph[state]:
            if neighbor not in visited:
                child = Node(neighbor, parent=current,
                             depth=current.depth + 1)
                stack.append(child)   # add to TOP

    return None

path = dfs(graph, 'A', 'F')
print("DFS Path:", path)   # might be ['A', 'C', 'F'] or different
Exam Hint
The ONLY difference between BFS and DFS code is: BFS uses deque + popleft(), DFS uses a regular list + pop(). Same structure, different data structure = completely different exploration order!

DFS Properties

  • Data Structure: Stack (LIFO) — regular Python list, use pop()
  • Optimal: No — path found may not be shortest
  • Complete: No — can get stuck in infinite depth/loops
  • Memory: Low — only stores current path nodes
  • Add: stack.append() | Remove: stack.pop() from top

5UCS — Uniform Cost Search

Finds the cheapest path in a weighted graph — uses a priority queue

UCS is BFS for weighted graphs. Instead of exploring level-by-level, it explores by total path cost — always expanding the cheapest node first. It uses a Priority Queue (min-heap).

Priority Queue (min-heap): always pop the smallest cost first
heappush: [(0, A), (1, B), (4, C)] ← after expanding A
heappop → (1, B) ← cheapest!
heappush: [(3, D), (4, C), (6, E)] ← after expanding B(cost=1+2=3, 1+5=6)
heappop → (3, D) ← cheapest!
Example

UCS Implementation

import heapq

# Weighted graph: each neighbor is (state, cost)
graph = {
    'A': [('B', 1), ('C', 4)],
    'B': [('D', 2)],
    'C': [('D', 1)],
    'D': []
}

def ucs(graph, start, goal):
    # Priority queue: (total_cost, node)
    pq = []
    start_node = Node(start, cost=0)
    heapq.heappush(pq, (0, start_node))

    visited = {}  # state → cheapest cost seen

    while pq:
        cost, current = heapq.heappop(pq)
        state = current.state

        if state == goal:
            print(f"Total cost: {cost}")
            return get_path(current)

        # If we've already found a cheaper path, skip
        if state in visited and visited[state] <= cost:
            continue
        visited[state] = cost

        for neighbor, edge_cost in graph[state]:
            new_cost = cost + edge_cost
            child = Node(neighbor, parent=current, cost=new_cost)
            heapq.heappush(pq, (new_cost, child))

    return None

path = ucs(graph, 'A', 'D')
print("UCS Path:", path)   # ['A', 'B', 'D']  cost=3 (cheaper than A→C→D cost=5)
Definition
heapq (min-heap): Python's priority queue. heapq.heappush(pq, item) inserts in sorted order. heapq.heappop(pq) removes and returns the smallest item. Items are tuples — compared element by element. Always push (cost, node) so cost is compared first.
Common Mistake
If two nodes have equal cost, heapq tries to compare Node objects directly, which causes a TypeError. Fix: add def __lt__(self, other): return self.cost < other.cost to the Node class. OR use a counter as a tiebreaker: (cost, counter, node).

UCS Properties

  • Data Structure: Min-Heap Priority Queue — import heapq
  • Optimal: Yes — always finds cheapest path
  • Complete: Yes
  • Memory: High
  • Push: heapq.heappush(pq, (cost, node)) | Pop: heapq.heappop(pq)

6IDS — Iterative Deepening Search

The best of both worlds — BFS optimality + DFS memory efficiency

IDS runs DFS multiple times, each time with a deeper depth limit. It starts with limit=0, then 1, then 2, etc. It's complete and optimal (like BFS) but uses very little memory (like DFS). The repeated work is acceptable because most nodes are at the deepest level.

IDS Iterations:
Depth 0: try A → not goal, done
Depth 1: try A→B, A→C → not goal, done
Depth 2: try A→B→D, A→B→E, A→C→F → FOUND F!
Example

IDS Implementation

# Step 1: Depth-Limited DFS (DFS with a max depth)
def depth_limited_dfs(node, graph, goal, limit):
    if node.state == goal:
        return node    # found it!

    if node.depth >= limit:
        return None    # hit depth limit — backtrack

    for neighbor in graph[node.state]:
        child = Node(neighbor, parent=node, depth=node.depth + 1)
        result = depth_limited_dfs(child, graph, goal, limit)
        if result:
            return result  # propagate success upward

    return None   # not found within this branch


# Step 2: IDS = run Depth-Limited DFS with increasing limits
def ids(graph, start, goal, max_depth=10):
    for depth in range(max_depth):
        print(f"Trying depth limit: {depth}")
        root = Node(start)
        result = depth_limited_dfs(root, graph, goal, depth)
        if result:
            return get_path(result)

    return None   # not found within max_depth

path = ids(graph, 'A', 'F')
print("IDS Path:", path)   # ['A', 'C', 'F']

IDS Properties

  • Data Structure: Stack (recursive DFS) + outer loop
  • Optimal: Yes (unweighted graphs)
  • Complete: Yes
  • Memory: Medium — only stores current path at each depth
  • Tradeoff: re-explores early nodes multiple times — acceptable because lower levels have fewer nodes

7Blind Search Algorithm Comparison

Side-by-side summary of all four algorithms — the exam always tests this

Algorithm Data Structure Weighted? Optimal? Complete? Memory Key Operation
BFS Queue (deque) ❌ Unweighted ✅ Yes ✅ Yes 🔴 High popleft()
DFS Stack (list) ❌ Unweighted ❌ No ❌ No 🟢 Low pop()
UCS Priority Queue (heapq) ✅ Weighted ✅ Yes ✅ Yes 🔴 High heappop()
IDS Stack + Loop ❌ Unweighted ✅ Yes ✅ Yes 🟡 Medium Recursive DFS

When To Use Which?

Use BFS when:
  • Unweighted graph
  • Need shortest path
  • Memory is not a concern
Use DFS when:
  • Memory is tight
  • Any path is acceptable
  • Graph has no cycles (or track visited)
Use UCS when:
  • Weighted graph
  • Need cheapest path
  • Edge costs vary
Use IDS when:
  • Memory is tight
  • Need optimal path
  • Graph depth unknown
Example

Complete Graph Search Simulator — BFS + DFS + UCS + IDS

from collections import deque
import heapq

class Node:
    def __init__(self, state, parent=None, cost=0, depth=0):
        self.state = state; self.parent = parent
        self.cost = cost; self.depth = depth
    def __lt__(self, other): return self.cost < other.cost

def get_path(node):
    path = []
    while node: path.append(node.state); node = node.parent
    return path[::-1]

graph = {'A':['B','C'],'B':['D','E'],'C':['F'],'D':[],'E':[],'F':[]}
weighted = {'A':[('B',1),('C',4)],'B':[('D',2)],'C':[('D',1)],'D':[]}

# BFS
def bfs(g, start, goal):
    q = deque([Node(start)]); vis = set()
    while q:
        n = q.popleft()
        if n.state == goal: return get_path(n)
        if n.state in vis: continue
        vis.add(n.state)
        [q.append(Node(nb, n, depth=n.depth+1)) for nb in g[n.state] if nb not in vis]
    return None

# DFS
def dfs(g, start, goal):
    s = [Node(start)]; vis = set()
    while s:
        n = s.pop()
        if n.state == goal: return get_path(n)
        if n.state in vis: continue
        vis.add(n.state)
        [s.append(Node(nb, n, depth=n.depth+1)) for nb in g[n.state] if nb not in vis]
    return None

# UCS
def ucs(g, start, goal):
    pq = []; heapq.heappush(pq, (0, Node(start, cost=0))); vis = {}
    while pq:
        cost, n = heapq.heappop(pq)
        if n.state == goal: print(f"Cost: {cost}"); return get_path(n)
        if n.state in vis and vis[n.state] <= cost: continue
        vis[n.state] = cost
        for nb, ec in g[n.state]:
            nc = cost + ec
            heapq.heappush(pq, (nc, Node(nb, n, cost=nc)))
    return None

# IDS
def dl_dfs(node, g, goal, limit):
    if node.state == goal: return node
    if node.depth >= limit: return None
    for nb in g[node.state]:
        r = dl_dfs(Node(nb, node, depth=node.depth+1), g, goal, limit)
        if r: return r
    return None

def ids(g, start, goal, max_d=10):
    for d in range(max_d):
        r = dl_dfs(Node(start), g, goal, d)
        if r: return get_path(r)
    return None

print("BFS:", bfs(graph, 'A', 'F'))   # ['A', 'C', 'F']
print("DFS:", dfs(graph, 'A', 'F'))   # ['A', 'C', 'F'] or different
print("UCS:", ucs(weighted, 'A', 'D'))# ['A', 'B', 'D'] — cost 3
print("IDS:", ids(graph, 'A', 'F'))   # ['A', 'C', 'F']
Exam Hint
The exam almost certainly asks you to implement one or more of these and trace the path. Key things to always include: (1) Node class with __lt__, (2) visited set, (3) get_path() function, (4) print the path and total cost.

Lab 4 Complete Summary

  • OOP: class + __init__ + self + super() for inheritance
  • BFS: deque + popleft() → shortest path (unweighted)
  • DFS: list + pop() → deep path, low memory, not optimal
  • UCS: heapq + (cost, node) → cheapest path (weighted)
  • IDS: DFS with increasing depth limit → optimal + low memory
  • All use: Node class, visited set, get_path() reconstruction
Practice Questions
Easy: What data structure does BFS use and why does it find the shortest path?

Answer: BFS uses a Queue (FIFO) — deque with popleft(). It finds the shortest path because it explores all nodes at distance 1 before any at distance 2, so the first time it reaches the goal, it must have taken the fewest steps.
