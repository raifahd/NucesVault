Lab 5 and 6 — Informed Search and Game Playing

1What is a Heuristic?

The "educated guess" that makes informed search smarter than blind search

In blind search (BFS/DFS/UCS), the algorithm has no idea which direction is closer to the goal — it just explores systematically. Informed search uses a heuristic function h(n) to estimate how far any node is from the goal, allowing it to prioritise promising paths.

Blind Search (BFS/DFS/UCS)

No knowledge of goal location. Explores everything systematically. Like walking a maze blindfolded.

vs
Informed Search (Greedy / A*)

Uses h(n) to estimate distance to goal. Prioritises nodes that seem closer. Like following a compass in a maze.

Definition
Heuristic function h(n): Estimates the cost from node n to the goal. It does NOT give the exact cost — it gives an estimate. A good heuristic is:
• Admissible: Never overestimates (required for A* to be optimal)
• Problem-specific: e.g., straight-line distance for maps, misplaced tiles for puzzles
Example

Heuristic Representation in Python

# A heuristic is just a dictionary: state → estimated cost to goal
heuristic = {
    'A': 6,   # from A, estimated 6 steps to goal
    'B': 4,
    'C': 2,
    'D': 3,
    'E': 1,
    'F': 0    # goal node always has h=0
}

# Access it like this:
def h(state):
    return heuristic[state]

# Example:
h('A')   # 6
h('F')   # 0  (goal)

Evaluation Functions — The Core Difference

AlgorithmFormulaWhat it means
Greedy BFSf(n) = h(n)Only considers estimated cost to goal — ignores path so far
A* Searchf(n) = g(n) + h(n)g(n)=cost so far + h(n)=estimate to goal — balanced
UCSf(n) = g(n)Only considers actual cost — no estimate (blind)
Exam Hint
Memorise: Greedy = h(n) only. A* = g(n) + h(n). UCS = g(n) only. A* is the most powerful because it balances what you've already spent (g) with what you expect to spend (h).

Key Takeaways

  • h(n) estimates cost from node n to goal — always 0 at goal
  • Greedy uses only h(n) — fast but not always optimal
  • A* uses g(n)+h(n) — optimal if heuristic is admissible
  • Heuristic must be admissible (never overestimate) for A* to guarantee optimal

2Greedy Best-First Search

Always chases the node that looks closest to the goal — fast but can be fooled

Greedy BFS selects the node with the smallest h(n) — the one that looks closest to the goal, ignoring how expensive it was to get there. It's like a tourist who always takes the "shortest looking" road without checking actual travel time.

Example

Greedy BFS Implementation

import heapq

graph = {
    'A': [('B', 1), ('C', 4)],
    'B': [('D', 2), ('E', 5)],
    'C': [('F', 1)],
    'D': [], 'E': [], 'F': []
}
heuristic = {'A':7, 'B':6, 'C':2, 'D':1, 'E':3, 'F':0}

class Node:
    def __init__(self, state, parent=None, cost=0):
        self.state=state; self.parent=parent; self.cost=cost
    def __lt__(self, other): return self.cost < other.cost

def get_path(node):
    path=[]
    while node: path.append(node.state); node=node.parent
    return path[::-1]

def greedy(graph, heuristic, start, goal):
    # Priority queue ordered by h(n) ONLY — ignores actual cost
    pq = []
    heapq.heappush(pq, (heuristic[start], Node(start)))
    visited = set()

    while pq:
        h_val, current = heapq.heappop(pq)
        state = current.state

        if state == goal:
            print(f"Greedy path: {get_path(current)}")
            return get_path(current)

        if state in visited:
            continue
        visited.add(state)

        for neighbor, edge_cost in graph[state]:
            if neighbor not in visited:
                child = Node(neighbor, current, edge_cost)
                # Push with h(neighbor) as priority — GREEDY
                heapq.heappush(pq, (heuristic[neighbor], child))

    return None

greedy(graph, heuristic, 'A', 'F')
# Greedy path: ['A', 'C', 'F']  (goes A→C because h(C)=2 < h(B)=6)

Greedy BFS Properties

  • Priority: h(n) — estimated cost to goal only
  • Not optimal — can find a longer/more expensive path
  • Not complete — can get stuck in loops
  • Fast — good when speed matters more than optimality

3A* Search Algorithm

The gold standard — balances actual cost and estimated remaining cost

A* (pronounced "A-star") combines UCS (knows the actual cost paid) and Greedy (estimates remaining cost). It's optimal and complete when the heuristic is admissible. It's the most widely used pathfinding algorithm in AI — used in GPS, games, robotics.

Definition
A* Evaluation Function: f(n) = g(n) + h(n)
• g(n) = exact cost from start to node n (what you've already paid)
• h(n) = estimated cost from n to goal (what you expect to pay)
• f(n) = estimated total cost of the cheapest path through n

Example

A* Implementation

import heapq

graph = {
    'A': [('B', 1), ('C', 4)],
    'B': [('D', 2), ('E', 5)],
    'C': [('F', 1)],
    'D': [], 'E': [], 'F': []
}
heuristic = {'A':7, 'B':6, 'C':2, 'D':1, 'E':3, 'F':0}

def astar(graph, heuristic, start, goal):
    # Priority queue ordered by f(n) = g(n) + h(n)
    pq = []
    start_node = Node(start, cost=0)
    heapq.heappush(pq, (heuristic[start], start_node))  # f=0+h(start)
    visited = {}

    while pq:
        f_val, current = heapq.heappop(pq)
        state = current.state
        g = current.cost  # actual cost so far

        if state == goal:
            print(f"A* path: {get_path(current)}, Total cost: {g}")
            return get_path(current)

        if state in visited and visited[state] <= g:
            continue
        visited[state] = g

        for neighbor, edge_cost in graph[state]:
            new_g = g + edge_cost           # actual cost to neighbor
            new_h = heuristic[neighbor]     # estimated remaining
            new_f = new_g + new_h           # total estimate

            child = Node(neighbor, current, cost=new_g)
            heapq.heappush(pq, (new_f, child))

    return None

astar(graph, heuristic, 'A', 'F')
# A* path: ['A', 'C', 'F'], Total cost: 5
# Trace: A(f=7) → B(f=1+6=7) or C(f=4+2=6) → pick C → F(f=5+0=5)
Exam Hint
The key insight: A* pushes (f_value, node) to the heap, where f = g + h. But it stores g (actual cost) in the node so you can compute new_g = parent.cost + edge_cost for children. The heuristic (h) is looked up from the dictionary for each node.

A* Properties

  • Priority: f(n) = g(n) + h(n)
  • Optimal: Yes — if heuristic is admissible (never overestimates)
  • Complete: Yes
  • Memory: High — stores all explored nodes
  • Best general-purpose search algorithm in AI

5Minimax Algorithm

Two-player game strategy — MAX wants high scores, MIN wants low scores

Minimax is how AI plays games like Tic-Tac-Toe and Chess. There are two players: MAX (the AI trying to win = maximise score) and MIN (the opponent trying to minimise the AI's score). Both are assumed to play perfectly.

MIN picks 3 (min of 3,12) and 2 (min of 8,2) → MAX picks 3 (max of 3,2)
Example

Minimax Implementation

class GameNode:
    def __init__(self, value=None, children=None):
        self.value = value       # None for internal nodes, int for leaves
        self.children = children or []

def minimax(node, is_max):
    # Base case: leaf node (no children)
    if not node.children:
        return node.value

    if is_max:
        # MAX player: choose maximum of children
        best = float('-inf')
        for child in node.children:
            val = minimax(child, False)  # opponent's turn next
            best = max(best, val)
        return best
    else:
        # MIN player: choose minimum of children
        best = float('inf')
        for child in node.children:
            val = minimax(child, True)   # our turn next
            best = min(best, val)
        return best

# Build the tree from the diagram above
# Leaves
leaf_3  = GameNode(value=3)
leaf_12 = GameNode(value=12)
leaf_8  = GameNode(value=8)
leaf_2  = GameNode(value=2)

# MIN nodes (level 1)
min1 = GameNode(children=[leaf_3, leaf_12])   # picks 3
min2 = GameNode(children=[leaf_8, leaf_2])    # picks 2

# MAX root
root = GameNode(children=[min1, min2])        # picks 3

result = minimax(root, is_max=True)
print(f"Optimal value: {result}")   # 3
Exam Hint
The minimax algorithm is recursive. At each call, the player alternates: if is_max=True → find max of children (each called with is_max=False), and vice versa. The recursion bottoms out at leaf nodes where you just return the value.

Minimax Key Points

  • Two players: MAX (maximise) and MIN (minimise)
  • Both players play optimally — no mistakes assumed
  • Recursive: MAX node returns max of children; MIN node returns min
  • Leaf nodes return their utility value
  • Used in: Tic-Tac-Toe, Chess, Checkers, Connect Four

6Alpha-Beta Pruning

Same result as Minimax — but skips branches that can never change the outcome

Alpha-Beta Pruning is Minimax with a shortcut: if we've already found a better option elsewhere, we can skip evaluating a whole branch. The final answer is identical to Minimax — we just evaluate fewer nodes to get there.

Definition
Alpha (α): The best value MAX can guarantee so far. Starts at -∞.
Beta (β): The best value MIN can guarantee so far. Starts at +∞.

Pruning condition: When β ≤ α — remaining branches cannot change the outcome.
• At MAX node: if current value ≥ β → stop (Beta Cut-off)
• At MIN node: if current value ≤ α → stop (Alpha Cut-off)
Example

Alpha-Beta Pruning Implementation

def minimax_ab(node, is_max, alpha=float('-inf'), beta=float('inf')):
    # Base case: leaf node
    if not node.children:
        return node.value

    if is_max:
        best = float('-inf')
        for child in node.children:
            val = minimax_ab(child, False, alpha, beta)
            best = max(best, val)
            alpha = max(alpha, best)   # update alpha (MAX's best)

            if beta <= alpha:
                break   # ← BETA CUT-OFF: MIN won't allow this branch
                        # MIN already has something ≤ beta elsewhere

        return best
    else:
        best = float('inf')
        for child in node.children:
            val = minimax_ab(child, True, alpha, beta)
            best = min(best, val)
            beta = min(beta, best)     # update beta (MIN's best)

            if beta <= alpha:
                break   # ← ALPHA CUT-OFF: MAX won't allow this branch
                        # MAX already has something ≥ alpha elsewhere

        return best

# Same tree as before
result = minimax_ab(root, is_max=True)
print(f"Alpha-Beta result: {result}")   # Still 3 — same as Minimax!

# Efficiency comparison
nodes_minimax = 0
nodes_ab = 0

def minimax_count(node, is_max):
    global nodes_minimax
    nodes_minimax += 1
    if not node.children: return node.value
    if is_max: return max(minimax_count(c,False) for c in node.children)
    else:      return min(minimax_count(c,True)  for c in node.children)

def ab_count(node, is_max, a=float('-inf'), b=float('inf')):
    global nodes_ab
    nodes_ab += 1
    if not node.children: return node.value
    if is_max:
        best=float('-inf')
        for c in node.children:
            best=max(best,ab_count(c,False,a,b)); a=max(a,best)
            if b<=a: break
        return best
    else:
        best=float('inf')
        for c in node.children:
            best=min(best,ab_count(c,True,a,b)); b=min(b,best)
            if b<=a: break
        return best

minimax_count(root, True)
ab_count(root, True)
print(f"Minimax nodes: {nodes_minimax}")
print(f"Alpha-Beta nodes: {nodes_ab}")
print(f"Nodes saved: {nodes_minimax - nodes_ab}")
Intuition for Alpha-Beta:

Imagine MAX is deciding between two options. Option 1 is worth 10 (already confirmed). While evaluating Option 2, at a MIN node, we see a child worth 3. MIN would pick 3 (or lower). Since 3 < 10, MAX would never choose Option 2 anyway — so we can stop evaluating Option 2's other children.

Exam Hint — 3 Key Facts
  1. Alpha-Beta gives the same result as Minimax — just faster
  2. α = MAX's best guarantee (starts -∞, only goes up)
  3. β = MIN's best guarantee (starts +∞, only goes down)

Alpha-Beta Key Points

  • Same optimal value as Minimax — just evaluates fewer nodes
  • Alpha (α): best MAX can guarantee — prune when value ≥ β (Beta cut-off)
  • Beta (β): best MIN can guarantee — prune when value ≤ α (Alpha cut-off)
  • Prune condition: β ≤ α → break out of the loop
  • Best case: reduces O(b^d) to O(b^(d/2)) — searches twice as deep!

Hard: Explain when and why pruning occurs in a 3-level game tree with leaves [3,12,8,2,4,6].

Answer: After MIN evaluates child1=3 of min1, it knows min1's value is ≤3. MAX (root) already has alpha=-∞, so alpha=3 after min1. When evaluating min2: MIN sees 8 first, beta becomes 8. Then sees 2, value=2, beta=2. Since beta(2) ≤ alpha(3) from root, no pruning yet because min2 returns 2 which is less. After min2, MAX has 3 and 2, alpha=3. When evaluating min3: MIN sees 4, value=4, beta=4. Since beta(4) ≤ alpha(3) is FALSE (4 > 3), we continue. MIN sees 6, but min3 already has 4, and 4>3... Actually: min3 value becomes min(4,6)=4, root picks max(3,2,4)=4. With AB: min3's first child is 4. beta=4. alpha=3. beta(4) ≤ alpha(3)? No (4>3). Evaluates second child 6. min3=4. root=max(3,2,4)=4.
