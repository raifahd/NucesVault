Module 1 — The Role of Algorithms in Computing

1Algorithms

What are algorithms and why are they worthwhile?

Definition
Algorithm: Any well-defined computational procedure that takes some value (or set of values) as input and produces some value (or set of values) as output in a finite amount of time. It is a tool for solving a well-specified computational problem.
Example

The Sorting Problem

Input: A sequence of n numbers ⟨a₁, a₂, ..., aₙ⟩.

Output: A permutation (reordering) ⟨a'₁, a'₂, ..., a'ₙ⟩ of the input such that a'₁ ≤ a'₂ ≤ ... ≤ a'ₙ.

An instance of this problem could be ⟨31, 41, 59, 26, 41, 58⟩, and a correct sorting algorithm will return ⟨26, 31, 41, 41, 58, 59⟩.

Correctness

An algorithm is said to be correct if, for every input instance, it halts with the correct output. An incorrect algorithm might not halt, or might halt with an incorrect answer. We generally only concern ourselves with correct algorithms, although sometimes controllable-error-rate incorrect algorithms can be useful in advanced scenarios (e.g., finding large prime numbers).

What kinds of problems are solved by algorithms?

  • Biological analysis: The Human Genome project uses algorithms to determine similarity between DNA sequences.
  • The Internet: Managing massive data volumes, routing traffic, and search engines using graph algorithms.
  • E-commerce: Public-key cryptography and digital signatures for safe transactions.
  • Resource allocation: Determining the optimal places to put oil wells or how to route planes efficiently (often modeled as linear programs).
Hard Problems (NP-Complete)

Most of this book is about efficient algorithms (algorithms that run in a reasonable amount of time). However, there is an interesting subset of problems known as NP-complete.

  • Nobody has ever found an efficient algorithm for an NP-complete problem.
  • Nobody has ever proven that an efficient algorithm cannot exist.
  • If an efficient algorithm exists for any one of them, then efficient algorithms exist for all of them.

Example: The Traveling-Salesperson Problem. A delivery company wants to select an order of delivery stops that yields the lowest overall distance traveled. This problem has no known efficient algorithm. If you encounter an NP-complete problem, you shouldn't waste time trying to find a perfectly optimal algorithm; instead, you should focus on an approximation algorithm that finds a good-enough solution quickly.

Key Takeaways

  • Algorithms are well-defined procedures that solve computational problems.
  • An algorithm is correct if it halts and produces the correct output for every possible input.
  • NP-complete problems have no known efficient exact solution, making approximation algorithms highly valuable.

2Algorithms as a Technology

Why efficiency matters even with infinite hardware

If computers were infinitely fast and memory was free, any correct method would do. However, computing time is a bounded, precious resource. Therefore, we should view algorithms as a technology, much like hardware. Total system performance depends on choosing efficient algorithms as much as on choosing fast hardware.

Different algorithms devised for the same problem can differ dramatically in efficiency. Let's compare two sorting algorithms:

Algorithm Running Time Growth Rate
Insertion Sort c₁n² Quadratic (faster for very small n)
Merge Sort c₂n log n Log-linear (much faster for large n)

Since log n grows much slower than n, the c₂n log n curve will inevitably drop below the c₁n² curve once n gets large enough, regardless of how much smaller the constant factor c₁ is compared to c₂.

Detailed Example

Hardware vs Algorithms

Suppose Computer A is 1,000 times faster than Computer B.

  • Computer A (Fast): Executes 10 billion (10¹⁰) instructions per second. Uses Insertion Sort programmed perfectly in machine language (2n² instructions).
  • Computer B (Slow): Executes 10 million (10⁷) instructions per second. Uses Merge Sort programmed poorly using a high-level language (50n log n instructions).

If we sort 10 million (10⁷) numbers:

  • Computer A takes:
    2(10⁷)² instructions / (10¹⁰ instructions/second)
    = (2 × 10¹⁴) / 10¹⁰
    = 20,000 seconds (more than 5.5 hours)
  • Computer B takes:
    50(10⁷) log(10⁷) instructions / (10⁷ instructions/second)
    ≈ 1,163 seconds (under 20 minutes)

Conclusion: By using an algorithm whose running time grows more slowly, the slower Computer B runs more than 17 times faster than Computer A! If we sorted 100 million numbers, Insertion Sort would take more than 23 days, while Merge Sort would take under four hours.

Key Takeaways

  • System performance depends as much on efficient algorithms as on fast hardware.
  • Asymptotic efficiency (how the algorithm scales) is far more important than constant factors or raw CPU speed for large input sizes.
Practice Q: Hardware limitation vs Algorithm efficiency

Question: Why is it that hardware advances alone cannot solve NP-complete problems?

Answer: NP-complete problems scale exponentially or worse (like 2ⁿ or n!). Even if a computer gets 1,000 times faster, an exponential algorithm might only allow you to increase the problem size by a tiny additive constant (e.g., from n=50 to n=60) before the running time balloons back to months or years. Algorithms dictate the shape of the curve; hardware only scales it.
