Module 3 — Characterizing Running Times

1Growth Rates

Understanding algorithm scalability

Imagine Algorithm A takes 100n steps and Algorithm B takes n² steps. Which one is faster?

The answer is: "it depends on n".

nA: 100nB: n²Faster Algorithm
101,000100B
505,0002,500B
10010,00010,000tie
20020,00040,000A
1,000100,0001,000,000A

The crossover happens exactly at n = 100. But which side matters more? We care about the large-n side because small inputs run fast on any algorithm! We study behaviour as n → ∞.

Definition
Growth rate (order of growth): The way an algorithm's running time increases as a function of the input size n, considering only the dominant term and disregarding constant factors.
What we discard
  • Constant factors (e.g., the 100 in 100n) - Because they are hardware/compiler dependent.
  • Lower-order terms (e.g., 5n in 3n² + 5n) - Because their contribution vanishes as n grows.
  • Small inputs - Because they finish fast regardless.

2Asymptotic Functions and Notation

The mathematical machinery for "eventually, ignoring constants"

Definition - Big-O (Upper Bound)
O(g(n)) = { f(n) : there exist positive constants c and n₀ such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀ }

Read as: f grows no faster than g.
Detailed Proof

Proving Big-O bounds with c and n₀

Claim: 4n² + 100n + 500 = O(n²)

We need to find positive constants c and n₀ such that 4n² + 100n + 500 ≤ c·n² for all n ≥ n₀.

Dividing both sides by n² gives: 4 + 100/n + 500/n² ≤ c.

This inequality is satisfied for many choices of c and n₀:

  • If we choose n₀ = 1, then 4 + 100/1 + 500/1 = 604, so c = 604 works.
  • If we choose n₀ = 10, then 4 + 100/10 + 500/100 = 19, so c = 19 works.
  • If we choose n₀ = 100, then 4 + 100/100 + 500/10000 = 5.05, so c = 5.05 works.

Since we found at least one pair (e.g., n₀ = 1, c = 604) that satisfies the inequality, the claim is proven.

Definition - Big-Omega (Lower Bound)
Ω(g(n)) = { f(n) : there exist positive constants c and n₀ such that 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀ }

Read as: f grows at least as fast as g.
Definition - Big-Theta (Tight Bound)
Θ(g(n)) = { f(n) : there exist positive constants c₁, c₂ and n₀ such that 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀ }

Read as: f grows at exactly the same rate as g.
Theorem: f(n) = Θ(g(n)) if and only if f(n) = O(g(n)) and f(n) = Ω(g(n)).

Little-o and little-omega

These denote strict bounds (analogous to < and >, rather than ≤ and ≥).

  • o(g): strictly slower. f(n) < c·g(n) for every c > 0.
  • ω(g): strictly faster. f(n) > c·g(n) for every c > 0.
Pro Tip
The Limit Method: A fast way to find bounds is computing L = lim(n→∞) f(n)/g(n):
  • If L = 0, f = O(g) and f = o(g) (f is strictly smaller)
  • If L = finite, ≠ 0, f = Θ(g) (f is the same rate)
  • If L = ∞, f = Ω(g) and f = ω(g) (f is strictly larger)

3Standard Notations & Common Functions

Mathematical tools for analysis

Exponentials and Polynomials

A polynomial in n of degree d is asymptotically positive if the leading coefficient is greater than 0. The function nᵈ is monotonically increasing for d > 0.

Any exponential function with a base strictly greater than 1 grows faster than any polynomial function. Mathematically: lim(n→∞) (nᵇ / aⁿ) = 0 for all a > 1, which implies nᵇ = o(aⁿ).

Logarithms

We use the following notations:

  • lg n = log₂ n (binary logarithm)
  • ln n = logₑ n (natural logarithm)
  • lgᵏ n = (lg n)ᵏ (exponentiation)
  • lg lg n = lg(lg n) (composition)

Any positive polynomial function grows faster than any polylogarithmic function: lgᵇ n = o(nᵃ) for a > 0.

The Iterated Logarithm Function

We use the notation lg* n (read "log star of n") to denote the number of times the logarithm function must be iteratively applied before the result becomes less than or equal to 1.

The iterated logarithm is a very slowly growing function:

  • lg* 2 = 1
  • lg* 4 = 2
  • lg* 16 = 3
  • lg* 65536 = 4
  • lg* (2⁶⁵⁵³⁶) = 5

Since the number of atoms in the observable universe is estimated to be about 10⁸⁰ (which is much less than 2⁶⁵⁵³⁶), we rarely encounter an input size n for which lg* n > 5.

Factorials

The factorial function n! grows very fast. A weak upper bound is n! ≤ nⁿ. A tighter bound is given by Stirling's approximation:

n! = √(2πn) (n/e)ⁿ (1 + Θ(1/n))

Using this, we can prove that n! = o(nⁿ), n! = ω(2ⁿ), and lg(n!) = Θ(n log n).

Fibonacci Numbers

Defined as F₀ = 0, F₁ = 1, and Fᵢ = Fᵢ₋₁ + Fᵢ₋₂.

Fibonacci numbers are related to the golden ratio φ = (1 + √5)/2 ≈ 1.618 and its conjugate φ̂ = (1 - √5)/2 ≈ -0.618. Both are roots of the equation x² = x + 1.

Specifically, Fᵢ = (φⁱ - φ̂ⁱ)/√5. Since |φ̂| < 1, this implies that Fᵢ = ⌊φⁱ / √5 + 1/2⌋. Thus, Fibonacci numbers grow exponentially.

Key Takeaways

  • Exponentials grow faster than polynomials.
  • Polynomials grow faster than polylogarithms.
  • Factorials grow faster than exponentials.
  • lg* n grows so slowly it can be considered a constant (≤ 5) for all practical applications.

4Exercises & Solutions

Test your understanding

Practice Q1: Prove 2n² + 3n + 1 = O(n²)

Answer:
For n ≥ 1: 3n ≤ 3n² and 1 ≤ n².
So the expression 2n² + 3n + 1 ≤ 2n² + 3n² + n² = 6n².
We can take constants c = 6 and n₀ = 1. This satisfies the Big-O definition.

Practice Q2: Prove n² + n ≠ O(n)

Answer:
Suppose it were. Then there exist c, n₀ > 0 such that n² + n ≤ cn for all n ≥ n₀.
Dividing by n gives n + 1 ≤ c.
Choosing n = max(n₀, c) yields a contradiction, because n + 1 will be strictly greater than c. Thus, it cannot be O(n).

Practice Q3: Is 2ⁿ⁺¹ = O(2ⁿ)?

Answer:
Yes. 2ⁿ⁺¹ = 2·2ⁿ, so choosing c = 2 and n₀ = 1 perfectly satisfies 2·2ⁿ ≤ c·2ⁿ.

Practice Q4: Is 2²ⁿ = O(2ⁿ)?

Answer:
No. 2²ⁿ = (2ⁿ)² = 2ⁿ·2ⁿ. The ratio 2²ⁿ / 2ⁿ = 2ⁿ → ∞. Coefficients can be absorbed by c, but changing exponents fundamentally changes the growth class.
