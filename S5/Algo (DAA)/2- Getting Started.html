1Insertion Sort

Sorting like a hand of playing cards

Insertion sort is an efficient algorithm for sorting a small number of elements. It works the way you might sort a hand of playing cards: you start with an empty left hand, and pick cards one by one from the table, inserting each into the correct sorted position in your left hand.

INSERTION-SORT(A, n)
1  for i = 2 to n
2      key = A[i]
3      // Insert A[i] into the sorted subarray A[1 : i - 1].
4      j = i - 1
5      while j > 0 and A[j] > key
6          A[j + 1] = A[j]
7          j = j - 1
8      A[j + 1] = key

Loop Invariants

We use loop invariants to help us understand why an algorithm is correct. We must show three things about a loop invariant:

Definition
Loop Invariant Properties:
  • Initialization: It is true prior to the first iteration of the loop.
  • Maintenance: If it is true before an iteration of the loop, it remains true before the next iteration.
  • Termination: When the loop terminates, the invariant gives us a useful property that helps show the algorithm is correct.
Detailed Proof

Proving Insertion Sort Correctness

Loop invariant: At the start of each iteration of the for loop of lines 1-8, the subarray A[1 : i - 1] consists of the elements originally in A[1 : i - 1], but in sorted order.

  • Initialization: Before the first iteration, i = 2. The subarray A[1 : i - 1] is just A[1]. A single element is trivially sorted, so the loop invariant holds.
  • Maintenance: The body of the for loop moves the values A[i - 1], A[i - 2], ... by one position to the right until it finds the proper position for A[i] (lines 4-7), and then it inserts the value of A[i]. The subarray A[1 : i] now consists of the original elements but in sorted order. Incrementing i for the next iteration preserves the invariant.
  • Termination: The loop terminates when i > n, which means i = n + 1. Substituting n + 1 for i in the wording of the loop invariant yields that the subarray A[1 : n] consists of the original elements in A[1 : n], but in sorted order. Hence, the algorithm is correct.

2Analyzing Algorithms

Predicting the resources an algorithm requires

We analyze algorithms to predict computational time. We use the RAM (Random-Access Machine) model of computation, where instructions execute one after another sequentially, and each data access takes constant time.

Detailed Example

Exact Mathematical Analysis of Insertion Sort

Let's analyze the INSERTION-SORT procedure precisely. Let cₖ be the cost of the k-th line. Let tᵢ denote the number of times the while loop test in line 5 is executed for that value of i.

LineCodeCostTimes Executed
1for i = 2 to nc₁n
2key = A[i]c₂n - 1
3// Insert A[i]...0n - 1
4j = i - 1c₄n - 1
5while j > 0 and A[j] > keyc₅Σ_{i=2}^{n} tᵢ
6A[j + 1] = A[j]c₆Σ_{i=2}^{n} (tᵢ - 1)
7j = j - 1c₇Σ_{i=2}^{n} (tᵢ - 1)
8A[j + 1] = keyc₈n - 1

Best Case (Already sorted array):
A[i] > key fails immediately every time, so tᵢ = 1 for every i.
T(n) = c₁n + c₂(n - 1) + c₄(n - 1) + c₅(n - 1) + c₈(n - 1)
This can be written as an + b. The best-case running time is a linear function of n, or Θ(n).

Worst Case (Reverse sorted array):
The element must travel past all i - 1 elements before it, so tᵢ = i for every i.
Using the arithmetic series sum formula, Σ_{i=2}^{n} i = n(n + 1)/2 - 1.
Substituting this into our equation yields a formula of the form an² + bn + c. The worst-case running time is a quadratic function of n, or Θ(n²).

Why focus on Worst-Case?

We usually concentrate on finding the worst-case running time for three reasons:

  1. It gives an upper bound guarantee. The algorithm will never take longer.
  2. For some algorithms, the worst case occurs fairly often (e.g., searching for an absent record in a database).
  3. The "average case" is often roughly as bad as the worst case. (e.g., in insertion sort, a randomly chosen element still needs to travel roughly halfway down the sorted subarray, resulting in a quadratic n² function).

3Divide-and-Conquer

Breaking problems into smaller subproblems

Many useful algorithms are recursive. They typically follow the divide-and-conquer paradigm, which consists of three characteristic steps:

Definition
  • Divide the problem into a number of subproblems that are smaller instances of the same problem.
  • Conquer the subproblems by solving them recursively. If the subproblem sizes are small enough, solve them straightforwardly as a base case.
  • Combine the solutions to the subproblems into the solution for the original problem.
Example

Merge Sort

  • Divide: Divide the n-element sequence to be sorted into two subsequences of n/2 elements each.
  • Conquer: Sort the two subsequences recursively using merge sort.
  • Combine: Merge the two sorted subsequences to produce the sorted answer.

The MERGE(A, p, q, r) procedure takes two sorted subarrays A[p : q] and A[q+1 : r] and merges them in Θ(n) time by repeatedly selecting the smallest unpicked element from the two subarrays.

Analyzing Divide-and-Conquer Algorithms

When an algorithm contains a recursive call, its running time is described by a recurrence equation.

For Merge Sort on an array of n elements:

  • Divide: Computes the middle of the subarray, taking Θ(1) time.
  • Conquer: Recursively solves two subproblems of size n/2, taking 2T(n/2) time.
  • Combine: The MERGE procedure takes Θ(n) time.

This yields the recurrence:

T(n) = 2T(n/2) + Θ(n)
Recursion Tree for Merge Sort

To understand the running time intuitively, imagine a tree:

  • At the top level (root), the cost is cn (where c is the constant hidden by the Θ).
  • At the next level down, there are two subproblems, each costing c(n/2). The total cost at this level is 2 × c(n/2) = cn.
  • At the next level, four subproblems each cost c(n/4). The total cost is 4 × c(n/4) = cn.

Each level of the tree has a total cost of cn. The tree bottoms out when the subproblem size drops to 1, which occurs at depth lg n. Thus, there are lg n + 1 levels. Adding the costs up gives cn(lg n + 1) = cn lg n + cn, which is Θ(n log n).
