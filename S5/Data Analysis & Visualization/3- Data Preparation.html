    Data Preparation & EDA

    1Why Data Cleaning Matters

    The time-intensive bedrock of any data science project

    Data preparation is often unglamorous, but it is the most critical phase of the DSLC (Stage 2). It consumes a massive portion of the total project time and directly dictates the validity of all downstream analysis.

    Time

    Time-Intensive Bedrock

    Data preparation consumes the largest slice of the total time spent on any data science project. It is unavoidable.

    Judgment

    Requires Human Judgment

    Cannot be fully automated. Every dataset requires human critical thinking, domain expertise, and contextual decision-making to clean properly.

    Learning

    Deep Domain Learning

    Hands-on cleaning builds intimate knowledge of data limits, quirks, and collection flaws essential for drawing valid downstream conclusions.

    Key Takeaways

    • Data cleaning isn't just a chore; it's where you truly learn the domain and dataset limitations.
    • It relies heavily on human judgment — automated tools can only go so far.

    2Data Cleaning vs Preprocessing

    Two distinct phases with different goals

    Though often grouped under "Data Preparation," cleaning and preprocessing serve different purposes in the DSLC.

    Data CleaningData Preprocessing
    What it isModifying raw data to be unambiguous, well-formatted, and readable by computers.Modifying clean data to meet specific algorithmic requirements.
    GoalCorrect errors, standardize column names, fix variable types, eliminate ambiguities.Prepare data objects specifically tailored for model execution or statistical analysis.
    ExamplesFixing typos, parsing dates, replacing impossible values (e.g., age=999).Scale normalization, one-hot encoding, featurization.
    Key RuleDo it without altering original source files.Applied on top of already-cleaned data.
    Judgment Calls
    For both cleaning and preprocessing, there are many different possible valid outputs. You must document the judgment calls you made and investigate whether your downstream results are stable under different, equally valid choices.
    Practice Q: Why is one-hot encoding considered preprocessing and not data cleaning?

    Answer: Data cleaning focuses on fixing errors and making the data correct and readable (e.g., ensuring all categorical states are spelled correctly). One-hot encoding changes the structure of the data (creating binary columns for each category) specifically because certain machine learning algorithms cannot natively handle categorical text. It's a transformation to meet algorithmic requirements, which defines preprocessing.

    3The 4-Step Procedure

    A structured workflow for tackling messy data

    1

    Domain Research

    Before touching the data, learn collection details, survey parameters, and domain constraints. Answer: What does each variable measure? How was data collected? What is the observational unit?

    2

    Load Data

    Import the data safely without modifying the raw source files directly. Figure out how data is stored, and if there are multiple tables, how they connect (keys).

    3

    Examine & Plan

    Identify messy traits and formulate precise action items. Determine what parts of the data are actually relevant to your specific question.

    4

    Execute Clean

    Apply the changes in encapsulated, reusable functions.

    Common Mistake
    Jumping straight to Step 4 (Execute Clean) without doing Step 1 (Domain Research). You cannot correctly fix anomalies if you don't understand the domain context of how they were generated.

    4Examine & Plan — Common Issues

    What to look for when inspecting raw data

    During the "Examine & Plan" phase, look for these common data anomalies to formulate your action plan:

    • 🚩 Invalid or inconsistent values: Typos, case differences ("New York" vs "new york"), impossible metrics (negative age).
    • 🚩 Improperly formatted missing values: "N/A", "?", "-99", or blanks instead of proper null/NaN indicators.
    • 🚩 Nonstandard data format: Data structured in "wide" format when "tidy" (long) format is needed, or nested JSONs.
    • 🚩 Messy column names: Spaces, special characters, or obscure abbreviations.
    • 🚩 Improper variable types: Numbers stored as strings, or dates stored as integers.
    • 🚩 Incomplete data: Missing rows, truncated sets, or missing related tables.
    Tidy vs Long Format
    In "tidy" data, every variable is a column, every observation is a row, and every value is a cell. Transforming wide data (where columns represent values of a variable, like Year_2020, Year_2021) into long format is a common cleaning task.

    5Common Preprocessing Steps

    Getting data ready for algorithms

    Once data is clean, you must often preprocess it to satisfy the algorithmic assumptions of models like Neural Networks or Linear Regression.

    Scale

    Standardization / Normalization

    Transforming numeric variables so they are on comparable scales (e.g., mean 0, variance 1). Critical for algorithms that rely on distance (like k-NN or PCA).

    Shape

    Gaussian Transformation

    Transforming skewed variables (e.g., taking the log) so they follow a more normal (bell-curve) distribution, satisfying assumptions of many statistical models.

    Encode

    One-Hot Encoding

    Splitting categorical variables into multiple binary (0/1) columns so machine learning models can process them mathematically.

    Create

    Featurization

    Creating entirely new variables from existing ones to capture complex patterns (e.g., extracting "season" from a date, or "word count" from text).

    6Best Practices & PCS

    Professional rules of engagement for data preparation

    Data preparation is where reproducibility and stability are most often lost. Follow these best practices to maintain the integrity of the DSLC.

    • 🛑 Never overwrite raw data: Always write code to transform memory-loaded objects, keeping original source files untouched. If you corrupt the source, you lose the ground truth.
    • 📦 Encapsulate in functions: Wrap cleaning steps in modular functions with explicit parameters for key judgment calls (e.g., `def clean_data(remove_outliers=True)`).
    • 📝 Document alternative choices: Record all subjective decisions in your documentation to enable later stability analysis.
    • 🧪 Investigate stability (PCS): Test whether downstream conclusions hold across different valid cleaning options. If a conclusion flips because you chose to impute rather than drop missing values, the finding is unstable.

    🎯 Practice Questions

    Q: Why is it critical to never overwrite the raw data files?

    A: If you overwrite the raw data file and make a mistake during the cleaning process, you permanently corrupt your ground truth. You can never go back and recover the original state to fix your error or try an alternative cleaning strategy. All transformations should happen via code on data loaded in memory.

    Q: Describe how the PCS framework applies to data cleaning.

    A: Data cleaning involves subjective judgment calls (e.g., how to handle outliers or missing values). Under the Stability principle of PCS, you should encapsulate these choices as function parameters and test multiple valid cleaning strategies. If your final modeling results or conclusions change drastically depending on which cleaning choice you made, your results are unstable and untrustworthy.

    Q: List three common issues to look for during the "Examine & Plan" stage.

    A: 1) Improperly formatted missing values (e.g., "-99" or "N/A" stored as strings instead of nulls). 2) Improper variable types (e.g., a "Date" column stored as a string or integer). 3) Inconsistent values/typos (e.g., case sensitivity issues like "Male" vs "male").
