Module 2 — The Data Science Life Cycle

1The Data Science Life Cycle — Overview

6 non-linear stages that every DS project travels through — expect to loop back

The DSLC is a framework for organizing every data science project. It is non-linear: discovering messy data at Stage 2 sends you back to Stage 1; poor results at Stage 5 send you back to Stage 2 or 4. It is a cycle, not a checklist.

1

Problem Formulation & Data Collection ✅ Mandatory

Define the domain question, find data sources, plan the train/validation/test split for predictability evaluation.

2

Data Cleaning, Preprocessing & EDA ✅ Mandatory

Fix messy data; transform it for algorithms; visually and numerically explore patterns relevant to the domain question.

3

Uncovering Intrinsic Structures ⚪ Optional

Dimensionality reduction (PCA) and clustering to discover hidden patterns — only if the domain question requires it.

4

Predictive / Inferential Analysis ⚪ Optional

Train ML models to predict outcomes, or run statistical inference to draw population-level conclusions.

5

Evaluation of Results ✅ Mandatory

Assess qualitatively (critical thinking, domain expert review) AND quantitatively (PCS: test set, stability, reproducibility, negative controls).

6

Communication & Updating Domain Knowledge ✅ Mandatory

Translate technical findings into accessible language for stakeholders. Document the non-linear path for reproducibility.

Rule
Stages 1, 2, 5, 6 = mandatory for every project. Stages 3, 4 = optional, included only when the domain question requires prediction, inference, or structure discovery.

Key Takeaways

  • DSLC = non-linear, iterative — expect frequent back-tracking
  • Mandatory: 1 (problem/data), 2 (clean/EDA), 5 (evaluate), 6 (communicate)
  • Optional: 3 (clustering/PCA), 4 (prediction/inference)
  • PCS is woven throughout: plan predictability at Stage 1, test stability at Stage 2, evaluate at Stage 5
Practice Q: Which DSLC stages are mandatory vs. optional, and why?

Answer: Mandatory (every project): Stage 1 (must define question + get data), Stage 2 (must clean + explore), Stage 5 (must evaluate quality), Stage 6 (must communicate). Optional: Stage 3 (clustering/PCA — only needed for structure discovery questions), Stage 4 (prediction/inference — only needed if the question requires a model or statistical conclusion).

Practice Q: Why is the DSLC non-linear? Give a concrete example of back-tracking.

Answer: Real DS constantly reveals surprises. Example: During Stage 2 (EDA), you discover that 40% of entries in a key variable are missing due to a data collection flaw. You must return to Stage 1 to collect additional data, revise the question, or find a supplementary source. Another example: Stage 5 evaluation reveals your model's predictions don't generalize (poor predictability) → return to Stage 2 for better feature engineering or Stage 4 for a different algorithm.

2Data Terminology

Rows, columns, variable types — the vocabulary of rectangular datasets

Most DS works with rectangular (tabular) data organized in rows and columns.

TermAlso CalledDefinitionExample
Observational UnitSample, Instance, RowEach individual entity measuredOne patient, one country, one house sale
Variable / FeatureColumn, AttributeA measured characteristicAge, blood pressure, sale price
Response / TargetOutcome, Label, YVariable we want to predict or explainReadmission risk, house price
PredictorFeature, Input, XVariables used to predict the responseAge, comorbidities, zip code

Variable Types

TypeDescriptionExamplesKey Note
Continuous NumericReal-valued, arithmetic meaningfulHeight (cm), temperature (°C), priceCan compute mean, SD, correlation
Discrete NumericInteger-valued counts# donations, # rooms, # visitsOften non-negative integers
Nominal CategoricalNamed groups, no orderCountry, blood type, speciesMust one-hot encode for most ML

Why Variable Types Matter
Many algorithms won't accept categorical inputs — you must one-hot encode them. Others assume variables are on comparable scales — you must normalize/standardize. Misidentifying types causes errors and misleading results.

Key Takeaways

  • Rows = observational units; Columns = variables/features
  • Target/response = what we predict; Predictor = what we use to predict it
  • 6 variable types: continuous, discrete, nominal, ordinal, date/time, text
  • Variable type determines preprocessing steps and which algorithms apply
Practice Q: Distinguish nominal from ordinal categorical variables.

Answer: Both are categorical (named groups), but ordinal has a meaningful ranking ("fair" < "good" < "excellent"), while nominal has no inherent order (country names — "USA," "France," "Japan" have no ordering). Ordinal variables can sometimes be mapped to integers; nominal variables need one-hot encoding for ML models that assume numeric inputs.

3Stage 1 — Problem Formulation & Data Collection

Start right: the question quality determines everything downstream

Stage 1 is where many DS projects fail before they start. Poorly framed questions and poorly designed data collection protocols create ceilings that no amount of sophisticated analysis can overcome.

Formulating the Right Question

  • 🤝 Collaborate with domain experts to translate broad goals into precise, data-answerable questions
  • 🎯 Identify the core objective — predicting patient risk vs. understanding systemic causes require very different approaches
  • 🔄 Align with available data — refine scope based on what's actually accessible. Never lock in a question before assessing data
  • ⚖️ Consider ethics — Is the analysis ethical? Could conclusions harm vulnerable populations?
Slide Example — Two Framings
Narrow (Risky)Better (Critical)
"Which website features make customers less likely to cancel?" "Why do customers cancel our subscription?"
Assumes the website is the problem. Misses root causes. Opens inquiry to all causes: pricing, product quality, UX, support, competition.

Data Collection & PCS Planning

PCS at Stage 1
Plan Predictability evaluation from the start. Ask: Can I collect data resembling future scenarios? If yes — do it now. If no — plan to split existing data into train/validation/test sets before any analysis begins.
Common Mistake
Collecting data without data scientist input. Domain experts often collect data in wrong formats, missing key variables, with no documentation. DS must be involved from the very beginning of collection design.

Key Takeaways

  • Ask: Is this the right, answerable, and ethical question?
  • Collaborate domain expert ↔ data scientist at Stage 1
  • Plan train/validation/test split at Stage 1, not after analysis begins
  • DS must be involved in data collection design — not just analysis
Practice Q: Why must data scientists be involved in data collection design?

Answer: Because they know what format, variables, sample size, and documentation are needed for valid analysis. Without DS input: data arrives in wrong format (PDF, not tabular), key variables are missing, there's no codebook, sample size is too small, or confounds are uncontrolled. These problems usually can't be fixed post-collection — you can't go back and re-measure. Early DS involvement prevents expensive collection mistakes.

4Stage 2 — Cleaning, Preprocessing & EDA

The messy, mandatory core that takes 50–80% of total project time

Data Cleaning vs. Preprocessing — Key Distinction

Data CleaningPreprocessing
GoalFix ambiguities, errors, inconsistencies — make data unambiguous for any useFormat clean data to meet the specific requirements of a particular algorithm
ExamplesFix column names, correct impossible values, handle missing values, standardize formatsNormalize numeric variables, one-hot encode categoricals, impute missing values, featurize
WhenFirst, before any analysisAfter cleaning, tailored to each algorithm
OutputClean dataset — one function, multiple versions via argumentsAlgorithm-ready dataset — different version for each algorithm
Data Preparation = Cleaning + Preprocessing
Data Preparation is the two-stage procedure: (1) clean data to remove ambiguities, and (2) preprocess it to meet algorithmic requirements. Both involve judgment calls that must be documented and tested for stability.
Featurization
Creating new variables from existing ones during preprocessing. Example: from a date column, create "month," "day of week," "days since last purchase," "season." This expands the feature space to capture patterns not directly in the raw data.
Data Snooping
Using the test set (or future data) during EDA, cleaning, or model development. Forbidden! Snooping leaks information from the test set into modeling decisions, making the predictability evaluation dishonest and overly optimistic.
PCS at Stage 2 — Write Functions
Encapsulate cleaning AND preprocessing in functions where each judgment call is a configurable argument. This directly enables: Stability testing (run with different args, check if conclusions change), Computability (reproducible), and easy generation of alternative dataset versions.

Key Takeaways

  • Cleaning = fix errors for any use; Preprocessing = prepare for specific algorithms
  • Data Preparation = Cleaning + Preprocessing (two-stage procedure)
  • Featurization = creating new derived variables during preprocessing
  • Write cleaning/preprocessing as functions with judgment-call arguments
  • Never snoop on the test set — it destroys the predictability evaluation
  • This stage typically consumes 50–80% of total project time
Practice Q: What is featurization and why is it done during preprocessing?

Answer: Featurization is the process of creating new variables (features) by applying transformations to existing variables. It's done during preprocessing (not cleaning) because it's specific to how an algorithm will use the data. Examples: from a "date of sale" column, extract "month," "year," "day of week" — each potentially capturing seasonal patterns. From text, extract word count or sentiment score. Featurization lets the model capture patterns that aren't directly encoded in the raw data.

Practice Q: Why must cleaning be written as a function with argument options?

Answer: Because data cleaning involves judgment calls (e.g., whether to impute or remove missing values, how to handle impossible entries). By making each choice a function argument, you can: (1) easily generate alternative cleaned datasets with different choices, (2) run your full analysis on each version to test whether conclusions are stable across cleaning choices (PCS-Stability), and (3) reproduce the cleaning exactly for any version (PCS-Computability). If results change drastically with different arguments, the instability is itself an important finding.

ML Model Alignment — The Three Realms

ModelAlgorithmic AssumptionData Best FitReal-World FitKey Pitfall
Linear / Logistic RegressionLinearity, error independenceWell-measured structured tabularProportional physical/economic relationshipsFails on non-linear threshold effects
Random Forest / XGBoostRecursive partitioning; no distributional assumptionsMixed types, missing values, high-dimensionalThreshold behaviors (medical triage, risk)Cannot extrapolate outside training range
Deep Neural NetworksHierarchical non-linear representationsHigh-dimensional unstructured (images, text, audio)Hierarchical/local structure (vision, NLP)Fits spurious correlations (watermark vs. pathology)
The Classic DNN Pitfall
A DNN trained to detect pneumonia from X-rays learned to recognize the hospital watermark on positive cases (an artifact of data collection), not actual radiological signs. It performed well on training data, failed at other hospitals. This is a Data Realm ↔ Reality Realm misalignment — the training data didn't represent reality accurately.

Key Takeaways

  • Stages 3 & 4 are optional — include only when the domain question demands it
  • Every algorithm assumes something — mismatched assumptions → untrustworthy results
  • Linear: simple, interpretable, fails non-linearity; Trees: robust, can't extrapolate; DNN: powerful, fits spurious patterns
  • Algorithm selection = aligning algorithmic assumptions with both the data realm and real-world realm
Hard Q: Why can't Random Forest reliably predict values outside its training range?

Answer: Random Forests are step-function estimators — predictions are averages of training points in leaf nodes. For a new x outside the training range, there are no similar training points. The model returns the average of the nearest extreme training examples — it cannot extrapolate the trend. This is a fundamental algorithmic limitation: RF partitions the observed feature space but has no mechanism to learn or project beyond it.

6Stages 5–6 — Evaluation & Communication

Where results are scrutinized and DS delivers real-world value

Stage 5 — Evaluation

Evaluation MethodWhat it checksExample
Qualitative / Critical ThinkingDoes the result make common sense? Does domain knowledge contradict it?"The model says ice cream causes drowning" → obvious spurious correlation
PCS — PredictabilityDoes the result hold on the held-out test set?Test accuracy vs. validation accuracy; large gap → overfitting
PCS — StabilityDoes the conclusion hold under perturbations to data/method?Run with different cleaning choices; conclusion should remain consistent
Domain Expert ReviewDo experts in the field validate or contradict the findings?Show oncologist the cancer detection results before publication
Negative ControlsDoes the method correctly return null when there's no true signal?Apply cancer detector to healthy tissue — should output "no cancer"
Negative Control
A test applied to a scenario where the true answer is null/zero. If your method finds a significant result in this null scenario, it has false positive problems — it's detecting noise, not real patterns.

Stage 6 — Communication

  • 🌉 Bridge the gap between technical methods and non-technical stakeholders
  • 📊 Use effective visualizations — clear, non-misleading, audience-appropriate
  • 📋 Document the full non-linear path — not just the polished final result, but the iterations and dead-ends, for reproducibility
  • 🔄 Update domain knowledge — share veridical findings with the broader field

Key Takeaways

  • Evaluate both qualitatively (common sense) AND quantitatively (PCS)
  • Negative controls are powerful false-positive checks
  • Domain expert review catches domain-nonsensical results
  • Communication = bridge technical ↔ non-technical; use accessible language and clear visuals
  • Document the iterative path for full reproducibility
Practice Q: What is a negative control and give a concrete example?

Answer: A negative control applies your method to a scenario where the true answer is known to be null — verifying your method doesn't produce false positives. Example: you have an algorithm to detect cancer gene signatures. Apply it to expression data from healthy tissue with no cancer markers. It should return "no cancer." If it returns "cancer" on healthy tissue, your method has a false positive rate problem that will contaminate results on real data. Another example: apply a time-series anomaly detector to purely random noise — it should find zero anomalies.

7The ROCCC Framework

5-point checklist for evaluating data trustworthiness before analysis

Before trusting any dataset, apply ROCCC. A dataset that fails multiple criteria should be replaced, or its limitations prominently disclosed in all results.

R

Reliable

Accurate, error-free, collected by a rigorous and unbiased process from a trusted organization.

O

Original

From the primary source — the entity that collected it. Not from a second-hand aggregator where context or accuracy may be lost.

C

Comprehensive

Contains all critical variables needed to answer the question. No major sampling bias or critical gaps.

C

Current

Up-to-date and reflects present conditions. Outdated data leads to obsolete, potentially dangerous conclusions.

C

Cited

Properly documented with metadata: who collected it, when, what each variable means, collection methodology.

Common Mistake — "It's All We Have"
Using data solely because it's available. A dataset failing 4 of 5 ROCCC criteria produces untrustworthy results regardless of analytical sophistication. Garbage in → garbage out. Either find better data or prominently disclose the limitations.

ROCCC — Flash Summary

  • Reliable — accurate, unbiased collection
  • Original — primary source, not aggregator
  • Comprehensive — contains all needed variables
  • Current — reflects present conditions
  • Cited — documented: who, when, what
Practice Q: Apply ROCCC to a 2003 hospital dataset from a general repository with no variable descriptions.

Answer: ❌ Original — from a general repository, not the collecting hospital; context/accuracy may be lost. ❌ Current — 2003 is >20 years old; medical practices, demographics, treatments have changed dramatically. ❌ Cited — no variable descriptions; unclear what each column actually measures. ⚠️ Comprehensive — scope unknown; single institution likely misses regional variation. Fails at minimum 3–4 of 5 criteria. Should be used only with major limitations disclosed, or replaced with better data.

Practice Q: Why is using a secondary data source (aggregator) worse than a primary source?

Answer: (1) Context loss — original variable meanings/units may be misrepresented. (2) Hidden transformations — aggregator may have already cleaned or modified data, introducing unknown assumptions. (3) Undocumented errors — mistakes introduced during data transfer are not documented. (4) Unverifiable methodology — can't verify collection rigor without the primary source. Primary sources provide full provenance, methodology, and transparency.

8ML Model Alignment to the Three Realms

Every algorithm makes assumptions — violate them and your results fail

Selecting an algorithm means selecting its assumptions. Those assumptions must align with your data realm and your real-world realm. This is three-realm thinking applied to model selection.

ModelCore AssumptionBest Data ContextReal-World FitFatal Pitfall
Linear / Logistic RegressionLinearity; error independenceStructured tabular, well-measured, few outliersProportional relationships: dosage↔response, price↔sizeFails on thresholds, interactions, non-linearity
Random Forest / XGBoostRecursive partitioning; no distribution assumedMixed types, missing values, high dimensionsThreshold effects: triage, risk scoring, creditCannot extrapolate beyond training range
Deep Neural NetworksHierarchical non-linear features; overparameterizedUnstructured high-D: images, audio, textHierarchical structure: vision, NLP, speechFits spurious correlations (artifact detection)
Selection Rule
Before choosing a model, ask: "Do the algorithmic assumptions match what I know about my data AND my real-world domain?" If not — the model is misaligned and PCS will expose this as poor predictability and instability.

Key Takeaways

  • Algorithm choice = assumption alignment with data realm + real-world realm
  • Linear: interpretable, fast, fails non-linearity
  • Trees: robust, handles mess, can't extrapolate
  • DNNs: powerful on unstructured data, prone to spurious artifact learning
Hard Q: A DNN trained on hospital X-ray data for pneumonia detection performs perfectly in training but fails at Hospital B. What went wrong in the three realms?

Answer: The Data Realm (Hospital A X-rays) was a poor approximation of Reality (pneumonia signs across all hospitals). Specifically: Hospital A's X-rays had a consistent watermark/stamp on all pneumonia-positive cases (data collection artifact). The DNN's Mental Construct (algorithm) learned to recognize this watermark rather than actual radiological pathology. Hospital B's X-rays lack this artifact → model fails. The fix: ensure training data is drawn from diverse sources (multiple hospitals) to better approximate the real-world Reality of pneumonia presentation across settings.

🚩 Exam Traps

Trap 1
"Stages 3 and 4 are always included." → FALSE. Optional — only when the domain question requires structure discovery, prediction, or statistical inference.
Trap 2
"Cleaning and preprocessing are the same." → FALSE. Cleaning = fix for any use; preprocessing = format for specific algorithm. Always clean first.
Trap 3
"Available data = suitable data." → FALSE. Apply ROCCC first. Data can fail all 5 criteria and still "be available."
Trap 4
"Looking at test set summary stats is okay — I'm not training on it." → FALSE. Any use of the test set during development constitutes data snooping. Even summary inspection can subconsciously influence decisions.

🎯 Practice Questions

Q: List the 6 DSLC stages and which are mandatory vs optional.

A: 1. Problem formulation & data collection ✅, 2. Cleaning, preprocessing & EDA ✅, 3. Uncovering intrinsic structures ⚪, 4. Predictive/inferential analysis ⚪, 5. Evaluation ✅, 6. Communication ✅. Optional = 3 and 4 only.

Q: Apply ROCCC to a dataset from Wikipedia (2015, no citations).

A: ❌ Reliable — Wikipedia is editable by anyone. ❌ Original — it's an aggregator. ⚠️ Comprehensive — unknown sampling. ❌ Current — 2015 may be outdated. ❌ Cited — no citations = no provenance. Fails 4–5 criteria. Not suitable for serious analysis.

Q: Why is writing cleaning as a function with argument options important for PCS?

A: Directly supports Stability (test if conclusions change when cleaning options change) and Computability (reproducible cleaning). If conclusions are stable across cleaning argument variations → trustworthy under PCS. If unstable → the instability is itself an important finding that must be reported.

Q: A linear regression fails to predict a drug with threshold effects. What went wrong?

A: Three-realm misalignment: the algorithmic realm (linear model) assumes proportional relationships, but the real-world realm exhibits threshold behavior (below threshold: no effect; above: sudden strong effect). The algorithm's assumptions don't match reality. Solution: use a threshold-capable model (piecewise linear, tree-based) that aligns with the real-world mechanism. PCS would detect this as poor predictability on the test set.

Chapter 2 — The Big Picture

  • DSLC = 6-stage non-linear cycle; mandatory: 1, 2, 5, 6; optional: 3, 4
  • Stage 1: frame the RIGHT question; involve DS in data collection from the start
  • Stage 2: Clean (any use) → Preprocess (algorithm-specific); document all judgment calls as function arguments
  • ROCCC = 5-point data quality checklist before trusting any dataset
  • Algorithm choice = matching assumptions to data realm + real-world realm (three-realm alignment)
