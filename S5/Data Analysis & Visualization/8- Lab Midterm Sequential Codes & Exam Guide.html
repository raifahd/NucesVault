The 5 Cardinal Sins of the DAV Lab Exam

Avoid These Common Mistakes That Cost 80% of Marks
  1. Inferring schema automatically in PySpark: Never do spark.read.option("inferSchema", "true").json(...) on mixed-type or schema-drifting files. It crashes runtime executors. Always use strict StructType DDL!
  2. Slicing unsorted MultiIndexes in Pandas: Slicing ranges on an unsorted index throws UnsortedIndexError. You must call df.sort_index(inplace=True) before slicing!
  3. Modifying DataFrame slices without .copy(): Filtering a DataFrame and mutating it raises SettingWithCopyWarning and causes silent bugs. Always append .copy()!
  4. Averaging pre-aggregated ratios in Power BI: Creating a calculated column Margin = Profit / Revenue and doing AVERAGE(Margin) commits the Ratio Fallacy. Always use a DAX measure: DIVIDE(SUM(Profit), SUM(Revenue))!
  5. Forgetting to sort Month Names by Month Number: In Power BI, months sort alphabetically ("Apr", "Aug", "Dec") unless you select the column and click Sort by Column → MonthNumber.

Self-Test Practice Questions

Q1: Why does performing a groupby followed by reindex against a Cartesian grid expose "silent absences"?
Worked Solution: Standard .groupby() only groups rows that actually exist in the raw transaction log. If a store sold zero units of a product in March, that combination never appears. Generating a Cartesian product of all stores $\times$ all products $\times$ all months with pd.MultiIndex.from_product() and reindexing against it forces missing combinations into the index, filled with 0 via fill_value=0.
Q2: What is the difference between Delta Lake append mode and a DeltaTable merge upsert?
Worked Solution: .write.format("delta").mode("append").save() blindly appends incoming batch rows, resulting in duplicate primary keys if rows were re-sent or updated. DeltaTable.merge() matches on primary key: if matched, it updates the existing record (SCD Type 1); if not matched, it inserts the new record, guaranteeing exactly-once primary key integrity.
Q3: Why is AVERAGE(Sales[ProfitMargin]) statistically invalid in Power BI?
Worked Solution: It calculates an unweighted arithmetic mean of ratios. A $10 order with 50% margin is weighted identically to a $1,000,000 order with 2% margin, distorting total company margin (Simpson's Paradox). The valid measure is DIVIDE(SUM(Sales[Profit]), SUM(Sales[Revenue])).

Step-by-Step API Extraction & Recursive Schema Discovery

Before flattening, you must inspect the structure without crashing. Here is the exam-tested defensive code template:

API Extraction & Recursive Schema Scanner
import requests
import json
import pandas as pd

url = "https://randomuser.me/api/?results=5"
response = requests.get(url, timeout=10)

# STEP 1: Defensive HTTP Status Validation
if response.status_code != 200:
    raise RuntimeError(f"API Request Failed: HTTP {response.status_code}")

payload = response.json()
records = payload.get('results', [])

# STEP 2: Recursive Arbitrary-Depth Key Scanner
def get_all_keys(obj, prefix=''):
    keys = []
    if isinstance(obj, dict):
        for k, v in obj.items():
            full_key = f"{prefix}.{k}" if prefix else k
            keys.append(full_key)
            keys.extend(get_all_keys(v, full_key))
    elif isinstance(obj, list) and len(obj) > 0:
        keys.extend(get_all_keys(obj[0], f"{prefix}[]"))
    return keys

print("Discovered Keys in First Record:")
print(get_all_keys(records[0])[:8])

# STEP 3: Safe Flattening with Underscore Separators
df_flat = pd.json_normalize(records, sep='_')

# STEP 4: Defensive Column Selection (Never crash on missing keys!)
desired_cols = ['gender', 'name_first', 'name_last', 'location_city', 'location_country', 'dob_age']
available_cols = [c for c in desired_cols if c in df_flat.columns]
df_clean = df_flat[available_cols].copy()

print(df_clean.head(2))
Discovered Keys in First Record: ['gender', 'name', 'name.title', 'name.first', 'name.last', 'location', 'location.street', 'location.city'] gender name_first name_last location_city location_country dob_age 0 female Eleanor Ross Dundee United Kingdom 44 1 male Lucas Schmidt Berlin Germany 32

Topic 2 Recap

  • Always check response.status_code == 200 before parsing .json().
  • Use pd.json_normalize(records, sep='_') to convert nested dicts into tabular columns.
  • Defensively filter columns using list comprehensions so unexpected missing keys do not raise KeyError.

Self-Test Practice Questions

Q1: Why is sep='_' preferred over sep='.' in pd.json_normalize?
Worked Solution: Dots (.) in column names break SQL engines, Spark schemas, and Pandas dot-accessors (e.g. df.location.city will fail or be ambiguous). Underscores (_) guarantee SQL and Delta Lake compatibility.
Q2: What happens if an API returns an HTTP 500 error and you immediately call response.json()?
Worked Solution: An HTTP 500 response usually returns an HTML error page or raw string text, not valid JSON. Calling response.json() immediately throws a json.decoder.JSONDecodeError, abruptly terminating execution.
Q3: How do you extract nested arrays inside JSON objects using json_normalize?
Worked Solution: Use the record_path argument. For example, if each user has a list of orders in data['orders'], call pd.json_normalize(data, record_path=['orders'], meta=['user_id', 'user_name']).

3Databricks Medallion & Delta Upsert

Architecting Bronze, Silver & Gold tiers with strict Schema-on-Read and ACID Delta merges

Phase 2 & 3 • Databricks PySpark Medallion Delta Lake

In modern data engineering, raw data is never ingested directly into production reporting tables. Databricks utilizes the Medallion Architecture to systematically guarantee data quality across three distinct tiers.

🏛️ The Medallion Lakehouse Architecture
BRONZE TIER (Raw Append)

• Raw source format (JSON / CSV / Kafka)
• Strict Schema-on-Read via StructType
• Audit metadata: current_timestamp()
• Append-only (never overwrite historical raw logs)

SILVER TIER (Cleansed Upsert)

• Deduplicated and type-cast
• Enforced Primary Keys via DeltaTable.merge()
• Derived business attributes (e.g. status flags)
• Single source of truth for analytical entities

GOLD TIER (Aggregated BI)

• Star Schema dimensional models (Fact / Dim)
• Pre-aggregated KPIs (Daily Sales, Monthly Churn)
• Highly optimized Parquet for Power BI / Tableau
• Overwritten or partitioned by calendar period

1. Schema-on-Read: Enforcing Strict DDL

StructType([StructField(name, dataType, nullable)])
Defines explicit Spark schemas. Prevents catastrophic job failures caused by mixed primitive types during runtime inference.
Bronze Tier Ingestion with Explicit DDL & Audit Metadata
from pyspark.sql.types import StructType, StructField, StringType, IntegerType, DoubleType, TimestampType
from pyspark.sql.functions import current_timestamp, col

# STEP 1: Define Explicit Schema-on-Read
bronze_schema = StructType([
    StructField("order_id", StringType(), False),
    StructField("customer_id", StringType(), True),
    StructField("order_date", StringType(), True),
    StructField("amount", DoubleType(), True),
    StructField("status", StringType(), True)
])

# STEP 2: Read Raw Stream / JSON with Enforced Schema
df_raw = spark.read.schema(bronze_schema).json("/FileStore/tables/raw_orders.json")

# STEP 3: Append Audit Metadata Column
df_bronze = df_raw.withColumn("ingest_timestamp", current_timestamp())

# STEP 4: Write to Bronze Delta Table (Append-only)
df_bronze.write.format("delta").mode("append").save("/mnt/lakehouse/bronze_orders")

2. Silver Tier: The Ultimate Delta Table Merge (Upsert)

If a customer updates their order status from PENDING to COMPLETED, appending the row creates a duplicate primary key. A blind overwrite erases all other orders. You must perform an ACID Upsert via DeltaTable.merge().

delta_table.alias("t").merge(df_source.alias("s"), condition).whenMatchedUpdate(...).whenNotMatchedInsert(...).execute()
Atomically updates existing records and inserts brand new records in a single transactional commit.
Silver Delta Merge (Upsert) Implementation
from delta.tables import DeltaTable

# Path to existing Silver Delta table
silver_path = "/mnt/lakehouse/silver_orders"

# If table does not exist, create it from initial batch:
# df_bronze.write.format("delta").save(silver_path)

# Load existing Silver table as DeltaTable object
silver_table = DeltaTable.forPath(spark, silver_path)

# Incoming updates batch from Bronze
df_incoming = df_bronze.dropDuplicates(["order_id"])

# Execute Atomic Upsert (Merge)
silver_table.alias("target").merge(
    source=df_incoming.alias("source"),
    condition="target.order_id = source.order_id"
).whenMatchedUpdate(set={
    "target.status": col("source.status"),
    "target.amount": col("source.amount"),
    "target.order_date": col("source.order_date"),
    "target.last_updated": current_timestamp()
}).whenNotMatchedInsert(values={
    "order_id": col("source.order_id"),
    "customer_id": col("source.customer_id"),
    "order_date": col("source.order_date"),
    "amount": col("source.amount"),
    "status": col("source.status"),
    "last_updated": current_timestamp()
}).execute()

print("Silver Upsert Merge Completed Successfully!")

Topic 3 Recap

  • Bronze: Ingest raw data with explicit StructType and append current_timestamp().
  • Silver: Deduplicate primary keys and perform an ACID DeltaTable.merge().
  • Gold: Create star schemas and aggregated KPI tables for direct Power BI consumption.

Self-Test Practice Questions

Q1: How does Delta Lake ensure ACID transactions under the hood?
Worked Solution: Delta Lake pairs columnar Parquet storage files with an ordered, JSON-based transaction log directory called _delta_log/. Every write operation generates an atomic commit file. Readers only see records validated by the latest commit, preventing dirty reads or partial writes.
Q2: What is the risk of using mode("overwrite") on a Silver table?
Worked Solution: Overwrite completely replaces the target table with only the records present in the current micro-batch. Any historical records not present in the current batch are wiped out.
Q3: When should you use whenNotMatchedBySourceDelete() in a Delta merge?
Worked Solution: When implementing a full synchronization with an operational database. If records deleted in the source database must also be removed from the Delta table, whenNotMatchedBySourceDelete() deletes unmatched target rows.

4Schema Drift, Stringified JSON & Joins

Handling mixed data types, JSONPath string extraction & distributed Spark SQL joins

Phase 3 • Advanced PySpark Schema Drift get_json_object

In production pipelines, upstream sources frequently change their formats without notice (Schema Drift). A column that was a nested JSON dictionary on Monday might arrive as an escaped JSON string or integer code on Tuesday. If Spark attempts to infer a unified schema across both files, it throws an AnalysisException: Cannot resolve column conflicting types.

The Quarantine Pattern for Conflicting Schema Drift

Formal Statement: When incoming files contain incompatible structural types across partitions, read the drifting field as a plain StringType() in Bronze. Defer field parsing to Silver using JSONPath extraction.

Intuitive One-Liner: Treat messy, changing data as dumb text first so your ingestion never crashes; surgically extract the clean pieces later!

get_json_object(col, "$.path.to.key")
Extracts scalar values from stringified or escaped JSON columns using standard JSONPath notation without compiling an explicit schema.
JSONPath ExpressionMeaningExam Example
"$.user_id"Top-level key in JSON stringExtracting account ID from raw clickstream log
"$.device.browser"Nested dictionary fieldExtracting nested browser from device telemetry
"$.items[0].sku"First element of embedded listExtracting primary product from order array
Quarantine Ingestion & get_json_object Extraction
from pyspark.sql.functions import get_json_object, col, when

# Day 1: {"event_id": "E1", "payload": {"device": "Mobile", "os": "iOS"}}
# Day 2: {"event_id": "E2", "payload": "{\"device\": \"Desktop\", \"os\": \"Windows\"}"}

# STEP 1: Quarantine by enforcing StringType on the drifting column
drift_schema = StructType([
    StructField("event_id", StringType(), False),
    StructField("payload", StringType(), True)
])

df_drift = spark.read.schema(drift_schema).json("/FileStore/tables/clickstream_drifting/*.json")

# STEP 2: Surgically extract attributes via get_json_object
df_silver_clean = df_drift.withColumn(
    "device_type", get_json_object(col("payload"), "$.device")
).withColumn(
    "os_name", get_json_object(col("payload"), "$.os")
).select("event_id", "device_type", "os_name")

df_silver_clean.show(2)

PySpark Distributed Joins & Broadcast Optimization

When joining a massive fact table (10,000,000 rows) with a tiny dimension lookup table (50 rows, e.g. Country Codes or Category Names), a standard shuffle join sends millions of rows across the network. You must use broadcast() to replicate the small table to every executor, eliminating network shuffle overhead.

df_fact.join(broadcast(df_dim), on="join_key", how="left")
Executes a Broadcast Hash Join. The small DataFrame is broadcast to all worker nodes in memory.
Broadcast Hash Join Example
from pyspark.sql.functions import broadcast

# Large transaction log (Millions of rows)
df_sales = spark.table("silver_sales")

# Small lookup table (Country code to Region name, 30 rows)
df_country_lookup = spark.read.csv("/FileStore/country_regions.csv", header=True)

# Optimized Broadcast Join
df_enriched = df_sales.join(
    broadcast(df_country_lookup),
    on="CountryCode",
    how="left"
)

df_enriched.write.format("delta").mode("overwrite").saveAsTable("gold_sales_by_region")

Topic 4 Recap

  • Neutralize schema drift by casting conflicting columns to StringType() in Bronze.
  • Extract nested attributes safely using get_json_object(col, "$.key").
  • Always wrap small lookup tables in broadcast() when joining with large transaction DataFrames.

Self-Test Practice Questions

Q1: Why does Spark fail if Day 1 has {"val": 100} and Day 2 has {"val": "N/A"} under inferSchema?
Worked Solution: Spark's automatic type inference cannot unify a primitive IntegerType with a primitive StringType within the same column across different input files, resulting in an AnalysisException during DAG resolution.
Q2: What is the maximum recommended size for a DataFrame passed to broadcast()?
Worked Solution: The default Spark threshold is 10 MB (controlled by spark.sql.autoBroadcastJoinThreshold), but manually broadcast DataFrames should ideally remain under a few hundred megabytes to prevent driver and executor out-of-memory (OOM) errors.
Q3: What does get_json_object return if the specified JSONPath key does not exist?
Worked Solution: It returns NULL (None) instead of throwing an exception, making it safe for defensive ETL.

Preventing the Dreaded `SettingWithCopyWarning`

The Root Cause of SettingWithCopyWarning
When you filter a DataFrame with sub_df = df[df['Qty'] > 0] and then assign sub_df['Revenue'] = ..., Pandas cannot determine if sub_df is a view or a separate copy in memory. It throws a warning, and your mutation might be silently discarded! Golden Rule: Whenever creating a filtered subset DataFrame, ALWAYS append .copy(): 
df_clean = df[~df['InvoiceNo'].str.startswith('C')].copy()
df_clean['Revenue'] = df_clean['Quantity'] * df_clean['UnitPrice']  # Safe!
df.fillna(value, method=None, inplace=False)
Replaces NaN / missing values. In the retail lab, missing sales combinations are filled with 0: df.fillna(0, inplace=True).

Topic 5 Recap

  • Use pd.to_datetime() with .dt.to_period('M') or .dt.strftime('%Y-%m') to group by monthly cohorts.
  • Filter strings with .astype(str).str.startswith('C') to isolate cancellations.
  • Always call .copy() when subsetting DataFrames to eliminate SettingWithCopyWarning.

Self-Test Practice Questions

Q1: What is the difference between df['Date'].dt.to_period('M') and df['Date'].dt.strftime('%Y-%m')?
Worked Solution: .dt.to_period('M') creates a Pandas PeriodIndex object with temporal awareness (supports chronological arithmetic, offsets, and time intervals). .dt.strftime('%Y-%m') returns a plain Python string. Both can be used as MultiIndex levels, but Period objects allow time-series frequency conversions.
Q2: Why must you wrap df['InvoiceNo'].astype(str) before calling .str.startswith('C')?
Worked Solution: In raw retail datasets, standard order numbers are integers (e.g. 536365), while cancellation orders are strings with a leading letter (e.g. C536379). Calling .str on integer or mixed object columns throws an AttributeError or skips integers. Explicitly casting with .astype(str) ensures uniform string evaluation.
Q3: How do you replace missing values in only specific columns using .fillna()?
Worked Solution: Pass a dictionary mapping column names to replacement values: df.fillna({'Quantity': 0, 'UnitPrice': df['UnitPrice'].median()}, inplace=True).

1. Constructing MultiIndexes: `set_index` vs `groupby`

Converts existing DataFrame columns into a hierarchical row index.
df.reset_index(level=None, drop=False)

2. Exposing "Silent Absences" with `from_product` & `reindex`

Silent Absence & The Cartesian Grid Principle

Formal Statement: pd.MultiIndex.from_product([Iterables]) generates the complete Cartesian product $L_1 \times L_2 \times \dots \times L_k$. Reindexing an aggregated DataFrame against this grid reveals non-occurring events.

Intuitive One-Liner: If a store sold zero units of a product in January, groupby() silently drops that row. from_product forces the empty coordinate to appear, and reindex(..., fill_value=0) fills it with $0$!

Generating the Full Cartesian Grid to Reveal Zero-Sales
# Sample Aggregated Sales
summary = df_clean.groupby(['Country', 'StockCode', 'Month']).agg(
    TotalRevenue=('Revenue', 'sum')
)

# Extract distinct coordinates
countries = df_clean['Country'].unique()
products = df_clean['StockCode'].unique()
months = df_clean['Month'].unique()

# STEP 1: Generate Complete Cartesian Grid (All combinations)
full_grid = pd.MultiIndex.from_product(
    [countries, products, months],
    names=['Country', 'StockCode', 'Month']
)

# STEP 2: Reindex to expose silent absences and fill with 0
summary_complete = summary.reindex(full_grid, fill_value=0)

print(f"Original GroupBy Rows:     {len(summary):,}")
print(f"Complete Cartesian Rows:   {len(summary_complete):,}")
print(f"Silent Absences Uncovered: {len(summary_complete) - len(summary):,}")
Original GroupBy Rows: 4,210 Complete Cartesian Rows: 48,000 Silent Absences Uncovered: 43,790 <-- These would be lost without from_product!

4. The Lexicographical Sorting Law & Index Properties

CRITICAL EXAM TRAP: UnsortedIndexError
Pandas uses binary search to slice MultiIndex levels. If the index is not sorted, any range slice (e.g. '21730':'22752') immediately crashes with:
UnsortedIndexError: 'Key length (3) was greater than MultiIndex sort depth (0)'
Solution: Always run df.sort_index(inplace=True) and verify df.index.is_monotonic_increasing!
Essential MultiIndex Inspection Properties
# Check number of hierarchical tiers
print("Index Levels:", summary.index.nlevels)          # Output: 3

# View level names
print("Index Names:", summary.index.names)             # ['Country', 'StockCode', 'Month']

# Extract all unique values from a specific level (0 = Country)
print("Countries:", summary.index.get_level_values('Country').unique())

# Rename index levels in-place
summary.index.set_names(['Nation', 'SKU', 'Period'], inplace=True)

# Verify lexicographical sorting
assert summary.index.is_monotonic_increasing, "Index is unsorted!"

Topic 6 Recap

  • pd.MultiIndex.from_product() generates all possible Cartesian combinations.
  • .reindex(full_grid, fill_value=0) exposes silent absences where transactions never occurred.
  • pd.MultiIndex.from_tuples() builds specific, non-Cartesian coordinate watchlists.
  • Always call .sort_index() to avoid UnsortedIndexError during range slicing.

Self-Test Practice Questions

Q1: When should you use from_product vs from_tuples?
Worked Solution: Use from_product when you need the complete $N \times M$ Cartesian grid of every possible combination (e.g. finding missing sales across all months for all items). Use from_tuples when you only want a specific list of coordinate pairs (e.g. a targeted audit list of 5 specific Country-Product combinations).
Q2: What is the return value of df.index.get_level_values(1)?
Worked Solution: It returns a 1D Index containing the values of the second hierarchical level (Index position 1) for every single row in the DataFrame, preserving row alignment.
Q3: Why does df.index.is_monotonic_increasing matter?
Worked Solution: It returns a boolean indicating whether the MultiIndex labels are strictly sorted in ascending lexicographical order. If False, any slice or range lookup will throw an UnsortedIndexError or return incorrect results.

Self-Test Practice Questions

Q1: How do you select all rows for product 'POST' across all countries and months using pd.IndexSlice?
Worked Solution: summary.loc[pd.IndexSlice[:, 'POST', :], :]. The first colon : matches all countries (Level 0), 'POST' matches the product (Level 1), the third colon matches all months (Level 2), and the final colon selects all columns.
Q2: What is the primary difference between df.xs() and df.loc[pd.IndexSlice]?
Worked Solution: .xs() cannot slice ranges (e.g. '2010-01':'2010-06'); it only accepts a single label. However, .xs() allows you to choose whether to drop or keep the sliced level via drop_level=True/False, whereas IndexSlice always retains the full index hierarchy.
Q3: What error is raised if you perform range slicing on an unsorted MultiIndex?
Worked Solution: UnsortedIndexError. Always run df.sort_index(inplace=True) before slicing.

Self-Test Practice Questions

Q1: What happens if you unstack an index level where combinations have no data?

Q1: Why does df['Rev'] / df.groupby(level='Country')['Rev'].sum() fail or produce NaN without transform()?

3. Calculated Columns vs DAX Measures: Simpson's Paradox

Calculated Columns vs DAX Measures

Calculated Columns: Computed during data refresh row-by-row. Stored permanently in RAM. Operates under Row Context.

DAX Measures: Computed on-the-fly dynamically when visuals render. Takes zero RAM. Operates under Filter Context.

The Ratio Fallacy: Why Measures are Mandatory
-- ❌ CRITICAL MISTAKE: Averaging a calculated column ratio
-- Average Discount = AVERAGE(Sales[DiscountPct])
-- This treats a 1-unit order the same as a 10,000-unit order!

-- ✅ CORRECT: Dynamic DAX Measure with DIVIDE
Total Revenue = SUM(Fact_Sales[Revenue])
Total Cost    = SUM(Fact_Sales[Cost])
Total Profit  = [Total Revenue] - [Total Cost]

Profit Margin = 
DIVIDE(
    [Total Profit], 
    [Total Revenue], 
    0 -- Safe alternate result if Revenue is 0
)

-- Time-Shifted Metric (Prior Year Sales)
Sales Prior Year = 
CALCULATE(
    [Total Revenue],
    SAMEPERIODLASTYEAR(Dim_Date[Date])
)

Q1: Why should relationships between Dimensions and Facts have Single cross-filter direction instead of Both?
Worked Solution: Bi-directional cross-filtering creates ambiguous filter paths in complex models, degrades query performance, and can lead to unexpected filter context propagation. Single direction ensures filters flow cleanly from Dimensions to Facts.

Worked Solution: DIVIDE(a, b, alternate) automatically intercepts division by zero and returns BLANK() or the specified alternate value (e.g. 0), whereas a / b displays Infinity or throws an error in visuals.

Worked Solution: When you need to slice or group data by the result (e.g. creating an Age Group category like "Youth", "Adult", "Senior" for use in slicers or axis labels).

Top 5 Professor Viva Voce Questions

Viva Q1: "Why did you use .copy() after filtering cancellations in Pandas?"
Model Answer: "Filtering a DataFrame creates a sliced view of the underlying NumPy memory block. If I mutate or create new columns on that view without .copy(), Pandas issues a SettingWithCopyWarning because it cannot guarantee whether changes persist to the parent or child. .copy() allocates independent memory and ensures mutation integrity."
Viva Q2: "Why can't you just use .groupby() to find missing product sales?"
Model Answer: "GroupBy is an aggregate of observed events. If a country had zero transactions for a product in January, that coordinate never existed in the log, so GroupBy silently ignores it. To expose zero sales, we must generate the theoretical Cartesian product using pd.MultiIndex.from_product() and reindex with fill_value=0."
Viva Q3: "What happens if you slice an unsorted MultiIndex using pd.IndexSlice?"
Model Answer: "Pandas raises an UnsortedIndexError. Range slicing relies on lexicographical binary search over the MultiIndex levels. If the index is unsorted, binary search fails. Calling .sort_index() sorts the levels and guarantees $O(\log N)$ slicing."
Viva Q4: "Why did you read drifting JSON as StringType in Databricks instead of letting Spark infer the schema?"
Model Answer: "If metadata arrives as a nested JSON object in Batch 1 but an escaped string or integer code in Batch 2, Spark's automatic inference cannot resolve the conflicting types and throws an AnalysisException. Reading as StringType() quarantines the data safely, allowing downstream extraction with get_json_object()."
Viva Q5: "Why is a dynamic DAX measure preferred over an averaged calculated column for Profit Margin?"
Model Answer: "Averaging row-level margin percentages commits the Ratio Fallacy (Simpson's Paradox), weighting small transactions equally with massive enterprise sales. A DAX measure evaluates under filter context dynamically: DIVIDE(SUM(Profit), SUM(Revenue)), guaranteeing mathematically accurate margin ratios."

Standard groupby only groups transactions that actually occurred. It drops non-events. from_product generates the complete Cartesian grid so missing sales show as 0.
6. What does `df.unstack('Month', fill_value=0)` do?
.unstack() pivots row index levels up into column headers. .stack() does the reverse (columns down to rows).
7. How does `.transform('sum')` differ from `.agg('sum')` during GroupBy operations?
.transform() returns an output aligned to the original DataFrame's index with identical row count, making percentage share calculations trivial.
8. What does `df.xs('2010-12', level='Month', drop_level=False)` achieve?
.xs() extracts a cross-section. Setting drop_level=False retains the sliced level in the MultiIndex.
9. In Power BI, why must Month Name be sorted by an integer Month Number?
Without explicit column sorting, text months will sort alphabetically, ruining trend line charts.
10. What is the standard list comprehension to flatten MultiIndex columns into clean 1D strings?
[f"{col[0]}_{col[1]}" for col in df.columns] concatenates the multi-tier tuple headers into a single clean string like Revenue_sum.
11. Why should you always use `pd.MultiIndex.from_tuples()` instead of `from_product()` for an audit watchlist?
from_tuples creates specific coordinate pairs (e.g. [('France', 'POST'), ('Germany', '22492')]), whereas from_product generates every possible combination.
12. What does `df.pivot_table(..., margins=True)` add to the resulting DataFrame?
margins=True adds an extra 'All' row and 'All' column computing overall grand totals.
13. In PySpark, when joining a 10M row sales table with a 50-row country lookup table, what optimization should you use?
Broadcasting copies the tiny lookup table to every worker node, eliminating expensive network shuffles of the 10M row table.
14. What does `df.index.nlevels` return?
.nlevels returns an integer representing the depth of the MultiIndex hierarchy.
15. How do you find the best-selling product in each country using a MultiIndex?
.idxmax() returns the exact index coordinate tuple containing the maximum value for each country group.
