State Space Search

1States and State Spaces

How AI views the world as a series of connected states

Many problems in AI involve answering questions like: Is there a guaranteed solution? Will the search loop infinitely? Is the solution optimal? To systematically answer these, AI frames problems using a State Space Search.

Definition
State: A snapshot of the world or the problem at a specific moment in time.
Definition
State Space: The complete set of all possible states that can be reached from the initial state through any sequence of valid actions.

Why use State Spaces?

By mapping out a problem as a state space, we transform decision-making into a mathematical search problem. The AI doesn't need to "understand" the nuances of a game; it just needs to find a path from the Initial State to the Goal State.

Example

The Tic-Tac-Toe State Space

Imagine a blank 3x3 board. This is our Initial State. When you place an 'X', the board transitions into a new state. Every legal move generates a branch to a new state. The collection of every possible board configuration (win, lose, draw, or mid-game) forms the Tic-Tac-Toe state space!

Common Mistake
State Space vs Game Tree Size
Students often think the number of states equals the number of nodes in the game tree. This is false! A game tree can have identical nodes (e.g., reaching the same board configuration through a different sequence of moves). The State Space only counts unique states.

Key Takeaways

  • A State represents a distinct configuration of the problem.
  • A State Space contains all possible distinct states.
  • Problem-solving in AI is largely about navigating through this state space efficiently.
Practice Questions
Easy: What is the initial state in a game of Chess?

Answer: The standard setup of the 32 pieces on the 8x8 board before any moves are made.

2Formal Definition & Graph Theory

Translating state spaces into math

To program a computer to solve a problem, we must formally define the state space using graph theory concepts.

Formal Definition of State Space [N,A,S,GD]

A State Space is represented as a four-tuple:

  • N: The set of nodes or states of the graph.
  • A: The set of arcs (links/edges) between nodes, representing legal moves or actions.
  • S: A nonempty subset of N containing the start state(s).
  • GD: A nonempty subset of N containing the goal state(s).
Definition
Solution Path: A sequence of arcs (a path) through the graph that starts at a node in S and ends at a node in GD.

Graph Theory Concepts

State spaces are almost always visualized and manipulated as graphs or trees. Here are the core definitions you need to know:

Term Definition
Graph A collection of nodes connected by arcs.
Directed Graph A graph where arcs have a specific direction (you can go A → B, but not necessarily B → A).
Parent & Child If an arc goes from N1 to N2, N1 is the parent and N2 is the child.
Rooted Graph A graph with a unique node (the root) from which all paths originate. (e.g., the empty board in a game).
Leaf (Tip) Node A node with no children (e.g., a finished game board).
Cycle (Loop) A path that visits the same node more than once.
Tree A specific type of graph where there is exactly one unique path between any two nodes. By definition, trees contain no cycles.
Pro Tip
Expert Systems and Graphs: In rule-based expert systems, nodes represent our knowledge of a problem at a stage, and arcs represent the application of an IF...THEN... rule to generate new knowledge.

Key Takeaways

  • State Space = [Nodes, Arcs, Start States, Goal States].
  • A graph is made of nodes (states) and arcs (actions).
  • Trees are cycle-free graphs with unique paths.

3Examples: Tic-Tac-Toe & TSP

Applying state spaces to classic problems

Let's look at how we represent classic AI problems using the State Space concepts we just learned.

1. Tic-Tac-Toe

We represent the state as a 3x3 array where each cell is empty (0), nought (1), or cross (2). The rules dictate that players alternate turns, placing their mark on an empty space.

By level 4 of this tree, it widens to 3,024 nodes! While the tree explodes in size, the state space is smaller because there are multiple ways to reach the exact same board configuration (e.g. playing Top-Left then Center vs Center then Top-Left results in identical states).

2. The Traveling Salesperson Problem (TSP)

Problem: Given a map of cities and the distances between them, find the path with the minimum distance that visits every city exactly once and returns to the starting city.

State Space Representation:

  • Nodes (N): Represent a set of visited cities and the current location.
  • Arcs (A): Labeled with a weight indicating the distance/cost of traveling between connected cities.
  • Start State (S): A home city with no other cities visited.
  • Goal State (GD): A state where the path contains a complete circuit (all cities visited and returned to home) with minimum cost.
Insoluble Variations
If cities are not always reachable directly from each other (e.g., to get from A to B you must go through C, but you've already visited C), there might be NO solution for that specific map!
The Complexity Nightmare
Exhaustive search is often impossible! There are 9! paths in tic-tac-toe. 1040 paths in Checkers, and 10120 paths in Chess! TSP has a complexity of (n-1)! cost-weighted paths. This is why we need smart Search Algorithms.

Key Takeaways

  • Tic-Tac-Toe state spaces are smaller than their game trees due to identical states.
  • TSP requires finding an optimal cost path in a massive factorial-complexity state space.
  • Exhaustive search is infeasible for non-trivial problems.
Practice Questions
Medium: What is the maximum depth of a Tic-Tac-Toe game tree?

Answer: 9 levels deep. There are 9 empty squares on the initial board, and one square is filled per turn. Therefore, the board is full (leaf node) at level 9 at the latest.

FAST Sessional-I • March 2025 Question 2 (15 Marks)

Question 1: The Formal Two-Variable State Space Search (Water Jug)

SP-2025 Exam Official Faculty Scheme

Problem Statement: Two integer variables X and Y have capacities 4 and 3 respectively (X ∈ [0,4], Y ∈ [0,3]). Initially, both are (0,0). The allowed operations are:

  • S1: Set X to 4 (Fill X).
  • S2: Set Y to 3 (Fill Y).
  • Z1: Set X to 0 if X ≠ 0 (Empty X).
  • Z2: Set Y to 0 if Y ≠ 0 (Empty Y).
  • T1: Transfer as much as possible from X to Y until Y is full or X is empty.
  • T2: Transfer as much as possible from Y to X until X is full or Y is empty.
Official Exam Solution & Working

Part a) BFS Tree & Nodes Expanded to reach target (2, 0):

Root: (0, 0) Level 1: (4, 0) via S1, (0, 3) via S2 Level 2 from (4, 0): (4, 3) via S2, (1, 3) via T1 Level 2 from (0, 3): (3, 0) via T2 Level 3: (1, 0) via Z2 from (1, 3); (3, 3) via S2 from (3, 0) Level 4: (0, 1) via T1 from (1, 0); (4, 2) via T2 from (3, 3) Level 5: (4, 1) via S1 from (0, 1); (0, 2) via Z1 from (4, 2) Level 6: (2, 3) via T1 from (4, 1); (2, 0) via T2 from (0, 2) -> GOAL!

Minimum and Maximum Nodes Expanded by BFS:

  • 11 or 12 nodes if the search terminates early on generation (when the goal state is inserted into the queue).
  • 12 or 13 nodes if the search terminates on expansion (when the goal state is popped off the queue).
  • (Both ranges were officially accepted by course instructors in the SP-2025 grading key!)

Part b) Minimum Nodes Expanded by Depth First Search (DFS):

Answer: 6 nodes. If DFS prioritizes the branch leading along the shortest path, it expands exactly the 6 states along the solution path without backtracking.

Part c) Optimal Solution Path Found:

(0, 0) --S2--> (0, 3) --T2--> (3, 0) --S2--> (3, 3) --T2--> (4, 2) --Z1--> (0, 2) --T2--> (2, 0) Using alternate operation symbols: F2 → T2 → F2 → T2 → E1 → T2

Part d) Heuristic Admissibility Analysis:

Consider a candidate heuristic estimating moves to reach (2,0). If h(0, 2) = 4, is h admissible?

Answer: NOT ADMISSIBLE. State (0, 2) is exactly 1 single move (T2) away from the goal (2, 0). Since h(0, 2) = 4 > 1, the heuristic overestimates the actual cost to reach the goal. By definition, an admissible heuristic must never overestimate: h(n) ≤ h*(n). Therefore, h is inadmissible.

FAST Sessional-I • Feb 2024 Question 1a (State Representation)

Question 2: "Solve-It Felix" Minimal State Space Formulation

SP-2024 Exam 5 Marks

Problem Statement: "Solve-It Felix" is a puzzle played on an M × N grid of cells. Agent Felix starts at (0,0) and needs to reach the exit cell containing the key. Felix can move {Up, Down, Left, Right}, but some cell boundaries are permanently locked walls that block entry. How would you formally represent the state of this puzzle so it can be used by a search algorithm? (Hint: Think about the minimum necessary information needed at any point during execution).

Official FAST Model Answer

Minimal State Vector:

State = (r, c) where r ∈ [0, M-1] and c ∈ [0, N-1]

Why only (r, c) is needed in the state:

  • The positions of the locked boundary walls and the destination key are static and invariant throughout the entire episode.
  • They belong to the problem description / environment definition, NOT the dynamic state representation.
  • Storing the wall layout or key position inside the state vector would be redundant and waste memory, multiplying hash comparison overhead.

Formal Formulation Summary:

  • Initial State: (rstart, cstart)
  • Actions(s): {Up, Down, Left, Right} filtered by: destination within grid bounds AND no locked wall on the crossed boundary.
  • Transition Model: Result((r, c), Right) = (r, c + 1), Result((r, c), Down) = (r + 1, c), etc.
  • Goal Test: Is (r, c) == (rkey, ckey)?
  • Path Cost: 1 per move (unit step cost).
FAST Mid-I • Fall 2017 Problem 1a (Branching & State Space Size)

Question 3: The 15-Puzzle Formal Mathematical Analysis

CS401 NUCES High-Yield Theory

Problem Statement: The 15-puzzle consists of a 4 × 4 frame containing fifteen numbered square tiles and one blank space. On average, 24 steps are needed to solve a puzzle optimally. Derive the average branching factor and calculate the theoretical number of states explored by uninformed search at depth d = 24.

Step-by-Step Derivation

1. Average Branching Factor Calculation: The blank space can be moved into adjacent tiles:

  • 4 Corner Cells: Blank has 2 legal moves → 4 × 2 = 8 moves.
  • 8 Edge (Non-Corner) Cells: Blank has 3 legal moves → 8 × 3 = 24 moves.
  • 4 Center Cells: Blank has 4 legal moves → 4 × 4 = 16 moves.
Average Branching Factor b = (8 + 24 + 16) / 16 = 48 / 16 = 3.0

2. Size of State Space: Total permutations of 16 items is 16!. However, exactly half of all permutations are mathematically unreachable (parity invariant for sliding tiles):

Reachable State Space Size = 16! / 2 ≈ 1.046 × 1013 states

3. Search Tree Nodes at Solution Depth d = 24:

Tree Search Node Count ≈ bd = 324 ≈ 282,429,536,481 (≈ 2.82 × 1011 nodes)

Conclusion: Pure blind search (tree search without cycle prevention) requires expanding over 282 billion nodes, making uninformed tree search physically impossible without graph search and heuristic guidance.

FAST Mid-I • Spring 2023 Question 1 (Multi-Goal State Representation)

Question 4: Pacman Grid Maze — When Is Position Insufficient?

SP-2023 Exam State Space Pitfall

Problem Statement: Pacman navigates an N × M grid maze to eat all food dots. A student defines the state space simply as Pacman's current coordinates: State = (x, y). Explain why this formulation is critically flawed and provide the correct state representation.

Model Solution

Why (x, y) is FLAWED:

If the state is only (x, y), the agent cannot distinguish whether it is visiting cell (x, y) for the first time (when a food dot is present) or returning to it later (after the food dot was already eaten). Furthermore, the goal test cannot verify if all food dots have been consumed!

Correct Minimal State Formulation:

State = (x, y, FoodBitmask) where FoodBitmask is a boolean tuple of length K indicating the status of each of the K food dots.

Total State Space Size: |S| = N × M × 2K. This proves that each additional dot doubles the search state space!

FAST Mid-1 Exam Pro-Tips for State Space Formulation

  1. Minimal State vs Environmental Invariants: Never include fixed walls, goal locations, or room dimensions inside the state tuple unless they dynamically change. State is strictly for dynamic information.
  2. Check Goal Test Feasibility: Ask yourself: "Can my GoalTest(state) function return true/false using ONLY the variables inside this state?" If not, your state is missing variables!
  3. Water Jug Node Expansion Counts: In BFS, always specify whether you are counting nodes expanded upon generation (push to frontier) or upon expansion (pop from queue). FAST faculty give full marks when this distinction is stated.
