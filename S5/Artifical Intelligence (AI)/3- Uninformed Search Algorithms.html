Uninformed Search Algorithms

1Direction of Search

Choosing where to begin our graph traversal

When searching through a state space, we have a choice of where to start: at the beginning and work forward, or at the end and work backward. These two strategies are called Data-Driven and Goal-Driven search.

Data-Driven Search

Also known as Forward Chaining.

  • Begins with the given facts/start state.
  • Applies legal moves or rules to change the state.
  • Generates new facts/states until a path that satisfies the goal condition is found.

Use when: The goal is poorly defined or there are many possible goals, but the starting data is clear.

Goal-Driven Search

Also known as Backward Chaining.

  • Begins with the goal we want to solve.
  • Determines what conditions must be true to reach this goal.
  • These conditions become subgoals. The process repeats backward until the given facts of the problem are reached.

Use when: The goal is clearly defined and there is a massive amount of starting data (most of which is irrelevant).

Branching Factor and Search Direction

Sometimes, the direction of search drastically changes the number of nodes we have to examine. This is determined by the Branching Factor (the average number of children a node has).

Example

Finding Ancestors

If a search algorithm attempts to find out if "I" am a descendant of "Fred", it can:

  1. Top-down (Data-Driven, Fred → Me): Branching factor is ~3 (each couple has roughly 3 children). At level n, there are 3^n nodes to check. By generation 5, that's up to 363 nodes!
  2. Bottom-up (Goal-Driven, Me → Fred): Branching factor is exactly 2 (everyone has exactly 2 parents). At level n, there are 2^n nodes. By generation 5, that's only 62 nodes!

Conclusion: If free to choose, search in the direction with the smaller average branching factor.

Practice Questions
Medium: You are designing a medical diagnosis AI. You have thousands of possible symptoms (facts) and a set of 20 possible diseases (goals). Should you use forward or backward chaining?

Answer: Backward Chaining (Goal-Driven). It's more efficient to pick a disease (goal) and work backward to see if the patient's symptoms match the required conditions, rather than starting with a headache (fact) and blindly generating thousands of possible medical outcomes.

2Backtracking Search

The foundation of all graph search algorithms

Backtracking Search is a fundamental algorithm. It begins at the start state and pursues a path down the tree until it either reaches a goal or a "dead end." If it hits a dead end, it backtracks to the most recent node that has unexamined siblings and tries a different branch.

The Four Tracking Lists

To prevent infinite loops and efficiently search the graph, backtrack uses four lists:

  • SL (State List): Lists the states in the current path being tried. If a goal is found, SL contains the solution path!
  • NSL (New State List): Contains nodes awaiting evaluation (the "fringe" or "frontier"). These are nodes whose descendants haven't been searched yet.
  • DE (Dead Ends): Lists states whose descendants have failed to contain a goal. Prevents the algorithm from retrying known useless paths.
  • CS (Current State): The state currently being evaluated (always the most recently added state to SL).
Pro Tip
Preventing Loops: Before adding a newly generated child node to NSL, the algorithm explicitly checks if it is already in SL, NSL, or DE. If it is, it discards it to prevent cycles!

Key Takeaways

  • Backtracking dives deep, hits a dead end, and reverses back to try another path.
  • It relies on SL to track the path, NSL for pending nodes, and DE to remember failures.

3Breadth-First vs Depth-First Search

The two classic uninformed search strategies

While backtracking gives us the basic mechanism (lists of nodes), we still have to decide the order in which we examine the nodes in the NSL (the frontier).

Breadth-First Search (BFS)

Structure: Queue (FIFO - First In, First Out)

Behavior: Examines all nodes at level n before proceeding to level n+1. It explores the graph layer by layer.

  • Complete: Yes! It will always find a solution if one exists.
  • Optimal: Yes! It will always find the shortest path to the goal node (assuming all step costs are equal).
  • Space Complexity: Exponential. It must keep all nodes of the current level in memory. Space is a massive problem for BFS.

Depth-First Search (DFS)

Structure: Stack (LIFO - Last In, First Out)

Behavior: Gets quickly into a deep search space. It follows a single branch all the way down before backtracking.

DFS goes deep down the left branch first!

  • Complete: No! If it goes down an infinite branch without a goal, it will never terminate.
  • Optimal: No! It might find a deep, convoluted solution even if a simpler one exists at a higher level on a different branch.
  • Space Complexity: Linear. Highly efficient memory usage, only storing the current path.
Exponential Explosion
Exponential-complexity search problems (like BFS) cannot be solved for large instances. If a tree has a branching factor of 10, searching to depth 12 with BFS would require 1 Petabyte of memory and 13 days of compute time!
Practice Questions
Easy: Which algorithm guarantees the shortest path (fewest edges) to the goal?

Answer: Breadth-First Search (BFS), because it checks every node at depth 1, then depth 2, etc. It cannot physically reach a goal at depth 5 without having first verified no goal exists at depth 4.

Medium: You are navigating a maze using an AI. Which algorithm is more memory efficient to use?

Answer: Depth-First Search (DFS). It only needs to store the current path it's walking down, requiring linear space O(b*d), whereas BFS would need to store the entire frontier of the search, requiring exponential space O(b^d).

4Iterative Deepening & Uniform-Cost Search

Upgrading our search algorithms

Iterative Deepening Search (IDS)

We want the optimality and completeness of BFS, but the memory efficiency of DFS. Iterative Deepening Search provides an excellent compromise.

How it works:

  1. Run a DFS with a depth limit of 0. If goal found, stop.
  2. Run a DFS with a depth limit of 1. If goal found, stop.
  3. Run a DFS with a depth limit of 2. If goal found, stop.
  4. Repeat, increasing the limit by 1 each time.

Pro Tip
Doesn't revisiting nodes waste time? Yes, but surprisingly little! Because the tree grows exponentially, the vast majority of nodes are at the deepest level. The overhead of re-searching the shallow top nodes is mathematically insignificant compared to searching the new, massive bottom layer.

Uniform-Cost Search (UCS)

BFS assumes every move (arc) costs exactly the same (e.g., 1). But in the real world (like the Traveling Salesperson Problem), travelling from City A to City B might cost 50km, while City A to City C costs 200km.

Definition
Uniform-Cost Search: Instead of expanding the shallowest node, UCS expands the node with the lowest cumulative path cost g(n).

How it works:

  • Structure: A Priority Queue ordered by cumulative path cost.
  • It expands in "cost contours" rather than depth contours.
  • The goal test is applied when a node is selected for expansion, not when it is first generated (because a cheaper path to that node might be found later!).
  • Optimality: Yes, UCS is guaranteed to find the optimal (cheapest) path as long as all step costs are non-negative.
Example

Uniform-Cost Search Trace

Consider navigating from Sibiu to Bucharest.

Key Takeaways

  • IDS: Combines BFS optimality with DFS memory efficiency by repeatedly running depth-limited DFS.
  • UCS: The cheapest-first search. Uses a priority queue to guarantee the lowest cost path in graphs with varying arc weights.
