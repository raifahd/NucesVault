A* Search & Heuristic Properties

1Algorithm A & The Evaluation Function f(n)

Balancing historical path expenditure with future heuristic promise

Pure greedy best-first search evaluates a node solely on its estimated remaining distance to the goal h(n). While greedy search makes fast initial progress, it suffers from a major defect: it is easily deceived down deep, expensive rabbit holes if the heuristic continually makes deceptive, overly-optimistic promises.

To prevent this, Algorithm A (Luger Chapter 4.2) introduces a balanced evaluation function:

f(n) = g(n) + h(n)
  • n: Any candidate state encountered in the search space.
  • g(n): The actual, known cost incurred so far along the path from the start state to node n (often measured as path cost or search depth).
  • h(n): The heuristic estimate of the cost required to go from node n to a goal state.
  • f(n): The estimated total cost of the cheapest complete solution path passing from start through node n to a goal.
Definition • Algorithm A (Luger Section 4.3.1)
If the Best-First Search algorithm (with OPEN and CLOSED lists) uses the evaluation function f(n) = g(n) + h(n), the resulting search algorithm is called Algorithm A.

Why the g(n) Component is Crucial

The g(n) component serves as a mathematical anchor that gives Algorithm A a breadth-first flavor:

  • If the search wanders down an unproductive, deep path because h(n) appears low, g(n) continuously accumulates at every step.
  • Eventually, g(n) grows so large that f(n) = g(n) + h(n) becomes worse than shallower, unexpanded candidate nodes on the OPEN list.
  • Algorithm A automatically abandons the deceptive deep path and forces the search to return to shallower alternatives!
Algorithm A Behavior in the 8-Puzzle (Luger Figure 4.15 & 4.16)

In Step 3 of the 8-puzzle search, states e and f both have the same heuristic value h=5 (5 tiles out of place).

State e is evaluated first at depth g=2, yielding f(e) = 2 + 5 = 7. Expanding e produces child h at depth g=3 with 5 tiles out of place (h=5).

Even though h has the exact same number of misplaced tiles (h=5) as state f, h has a higher depth cost (g=3), giving f(h) = 3 + 5 = 8. Meanwhile, shallower node f sitting on OPEN has f(f) = 2 + 5 = 7.

The depth component g(n) forces Algorithm A to abandon the deep child h and switch directly to expand the shallower state f, which directly leads to the goal!

2Algorithm A* & The Admissibility Theorem

Guaranteed minimal cost path through admissible heuristic bounds

Does Algorithm A always find the optimal (cheapest) path? Not necessarily. If the heuristic h(n) overestimates the true remaining cost, it can prematurely dismiss an optimal path because it looked "too expensive", and instead choose a suboptimal path.

To guarantee that Algorithm A terminates with the optimal solution, we must constrain h(n) with the property of Admissibility.

Definition • Admissibility & Algorithm A* (Luger Section 4.3.1)
  • A search algorithm is admissible if, for any graph, it always terminates in an optimal (minimal cost) solution path whenever a path from the start to a goal state exists.
  • Let h*(n) denote the actual, true minimal cost of the shortest path from node n to a goal.
  • A heuristic function h(n) is admissible if it never overestimates the true cost to reach the goal:
    h(n) ≤ h*(n)   for all states n, and h( Goal) = 0
  • If Algorithm A is used with an admissible heuristic h(n) ≤ h*(n), the algorithm is called Algorithm A* (pronounced "A-Star").
Fundamental Theorem of A*
Theorem: All A* algorithms are admissible.
Any search algorithm that uses f(n) = g(n) + h(n) with an admissible heuristic h(n) ≤ h*(n) is mathematically guaranteed to find the minimal cost path to a goal, if a solution exists.

Formal Mathematical Proof of the Admissibility of A* (Luger & Nilsson 1980)

We prove this by contradiction. Suppose A* terminates at a suboptimal goal state G2 instead of an optimal goal state G.

  1. Let C* be the cost of the optimal path to goal G. Because G is optimal, f*(G) = g*(G) = C*.
  2. Because G2 is suboptimal, its path cost is strictly greater than the optimal cost:
    g(G2) > C*
  3. At any goal state, the remaining heuristic cost is zero: h(G2) = 0. Therefore:
    f(G2) = g(G2) + h(G2) = g(G2) > C*
  4. Now consider the optimal path from Start to G. Since this path exists and has not been fully explored yet, there must exist at least one unexpanded node n on the optimal path currently sitting on the OPEN list.
  5. For this unexpanded node n:
    f(n) = g(n) + h(n)
  6. Because n lies along an optimal path discovered so far, g(n) = g*(n). Furthermore, because h(n) is admissible (h(n) ≤ h*(n)):
    f(n) = g*(n) + h(n) ≤ g*(n) + h*(n) = f*(n)
  7. Because n is on the optimal path to G, the true cost through n to G is exactly C*:
    f(n) ≤ C*
  8. Combining equations (3) and (7):
    f(n) ≤ C* < f(G2)
    f(n) < f(G2)
  9. The Contradiction: A* always selects the node from OPEN with the lowest f value. Since f(n) < f(G2), node n must be selected for expansion before G2 could ever be selected!
  10. This holds for every node along the optimal path up to and including optimal goal G. Therefore, A* can never select G2 while an optimal path exists on OPEN. A* must terminate with the optimal path C*. ■ (Q.E.D.)

Breadth-First Search as an A* Algorithm

Notice that standard Breadth-First Search (on graphs with uniform edge costs) is simply a special case of A* where the heuristic function is identically zero:

h(n) = 0   for all n
Since actual remaining distance is always ge 0, 0 ≤ h*(n) is trivially true. Thus, BFS is an admissible A* search, which explains why BFS always finds the shallowest goal. However, because h(n) = 0 contains zero domain knowledge, BFS explores every node blindly in all directions.

3Monotonicity (Consistency) & The Reopening Theorem

Local admissibility and the guarantee that closed nodes never reopen

Admissibility requires that h(n) is a global lower bound on the true remaining cost to the goal (h(n) ≤ h*(n)). However, an admissible heuristic may still be "locally erratic"—it might fluctuate wildly between parent and child nodes, meaning a node could initially be reached along a suboptimal path before being rediscovered along a cheaper path later in the search.

This brings us to a stronger, local property: Monotonicity (also known as Consistency).

Definition • Monotonicity / Consistency (Luger Section 4.3.2)
A heuristic function h is monotone (consistent) if:
  1. For all states ni and any successor state nj of ni:
    h(ni) - h(nj) ≤ c(ni, nj)
    or equivalently:
    h(ni) ≤ c(ni, nj) + h(nj)
    where c(ni, nj) is the actual step cost of traveling from ni to nj.
  2. The heuristic evaluation of the goal state is zero:
    h( Goal) = 0
Geometric Intuition: The Triangle Inequality
The monotonicity condition h(ni) ≤ c(ni, nj) + h(nj) is a direct expression of the Triangle Inequality in metric spaces. Going directly from ni to the Goal can never cost more than taking the intermediate step to nj and then going from nj to the Goal!

Mathematical Proof: Monotonicity Implies Admissibility (Lecture 8 Slide 20 & Luger 4.3.2)

Let (s1, s2, s3, dots, sk, sg) be the sequence of states along the optimal path from any state s1 to the goal sg. By the definition of monotonicity:

h(s1) - h(s2) ≤ c(s1, s2)
h(s2) - h(s3) ≤ c(s2, s3)
h(s3) - h(s4) ≤ c(s3, s4)
...
h(sg-1) - h(sg) ≤ c(sg-1, sg)

Summing both sides of all inequalities, the intermediate heuristic terms cancel out telescopically:

[h(s1) - h(s2)] + [h(s2) - h(s3)] + ... + [h(sg-1) - h(sg)] ≤ ∑ c(si, si+1)

Since all intermediate terms cancel, we are left with:

h(s1) - h(sg) ≤ Cost(s1, sg)

Because h(sg) = h(Goal) = 0, this simplifies directly to:

h(s1) ≤ Cost*(s1, sg) = h*(s1)

Therefore, any monotonic heuristic is guaranteed to be admissible. ■ (Q.E.D.)

The Closed-Node Reopening Theorem (High Exam Importance!)
Why does monotonicity matter in practice?
If a heuristic is monotonic, the values of f(n) along any path are monotonically non-decreasing (f(nj) ≥ f(ni)).

This guarantees that the first time A* selects a node n from the OPEN list for expansion, the algorithm has already found the optimal minimal-cost path to that node!

Consequence: If a state is encountered that is already on the CLOSED list, it can be immediately discarded. The algorithm never needs to reopen or update closed nodes! This drastically simplifies implementation and boosts execution speed.

4Informedness & The Dominance Theorem

Quantifying heuristic quality and search pruning power

Suppose you have two admissible heuristics, h1 and h2. Both guarantee finding the optimal solution. How do we determine which heuristic is "better"? This is the property of Informedness.

Definition • Informedness & Dominance (Luger Section 4.3.3)
For two admissible heuristics h1 and h2, if:
h2(n) ≥ h1(n)   for all states n in the search space
and h2(n) > h1(n) for at least some non-goal state, then heuristic h2 is said to be more informed than h1 (or h2 dominates h1).

The Dominance Theorem

If h2 dominates h1, then A* using h2 will never expand more nodes than A* using h1 (except possibly for some nodes on the contour where f(n) = C*).

Nodes Expanded by A*(h2) ⊆ Nodes Expanded by A*(h1)
Comparing Informedness Levels in the 8-Puzzle

Consider three heuristics for the 8-puzzle:

  • h0(n) = 0 (Equivalent to Breadth-First Search).
  • h1(n) = Number of tiles out of place.
  • h2(n) = Sum of Manhattan distances of all tiles.

Because every misplaced tile is at least 1 square away from its goal position, the Manhattan distance h2(n) is always greater than or equal to the count of misplaced tiles h1(n). Furthermore, both are strictly bounded from above by the true minimal moves h*(n):

h0(n) ≤ h1(n) ≤ h2(n) ≤ h*(n)

Therefore, h2 dominates h1, which in turn dominates h0. In empirical benchmarks (Luger Figure 4.18), searching to depth 14:

  • BFS (h0): Expands over 3,000,000 nodes!
  • A* with h1 (Misplaced): Expands approximately 540 nodes.
  • A* with h2 (Manhattan): Expands only 130 nodes!

The Computational Trade-off

While more informed heuristics drastically prune the search graph, they often require more CPU cycles to calculate per state. The ideal heuristic balances pruning power with computational overhead so that total wall-clock time is minimized.

1. Heuristic h1: Count of Tiles Out of Place (Hamming Distance)

Count how many numbered tiles do not occupy their designated position in the goal state. (The blank space is not counted as a tile).

  • Admissibility: Since each misplaced tile requires at least 1 move to reach its goal position, h1(n) ≤ h*(n). Hence, h1 is admissible.
  • Limitation: It fails to capture distance. A tile that is 1 square away receives the same penalty (1) as a tile that is across the entire board (4 squares away).

2. Heuristic h2: Sum of Manhattan Distances

Sum the vertical and horizontal grid distances of each tile from its target position:

h2(n) = ∑i=1..8 (|xi - xigoal| + |yi - yigoal|)

  • Admissibility: Because tiles cannot move through other tiles or move diagonally, a tile requires at least its Manhattan distance in moves. Hence, h2(n) ≤ h*(n). h2 is strictly admissible and dominates h1.

3. Heuristic h3: Direct Tile Reversals & Nilsson's Sequence Score

Both h1 and h2 treat tiles independently and fail to acknowledge the extreme difficulty of tile reversals (where two adjacent tiles are in reverse order of their goal positions, e.g., tiles 1 and 2 are adjacent but swapped).

  • Two reversed tiles cannot simply slide past each other on a single track. One tile must take a long, convoluted detour around the board to let the other pass!
  • Direct Tile Reversal Heuristic: Multiply the number of direct adjacent reversals by 2 (or a small multiplier):
    h(n) = Manhattan(n) + 2 × DirectReversals(n)
  • Nilsson's Sequence Score (Luger Section 4.2): A sequence score S(n) checks the non-central tiles in clockwise order: A tile gets a score of 2 if it is not followed by its proper successor, and the center tile scores 1 if non-empty. The heuristic is:
    h3(n) = P(n) + 3 × S(n)
    where P(n) is the Manhattan distance.

Consider finding the shortest route from City A to City E on a grid map with intermediate nodes B, C, and D. Let the evaluation function be e(n) = c(n) + d'(n), where c(n) is the accumulated path cost from A, and d'(n) is the estimated grid distance to E.

Step Selected Node (n) Accumulated Cost c(n) Heuristic d'(n) e(n) = c + d' Action & OPEN Priority Queue State
1 A (Start) 0 - - Generate B and C. Both evaluate to e=3. Tie-break leftmost: pick B.
2 B 1 2 3 Expand B: generates E with cost c(E)=4, d'(E)=0 &implies; e(E)=4. Put on OPEN: [C(3), E_via_B(4)].
3 C 1 2 3 C is lowest on stack (3 < 4). Expand C: generates D with e(D)=3. OPEN: [D(3), E_via_B(4)].
4 D 2 1 3 D has e=3 < 4. Expand D: generates E with cost c(E)=3, d'(E)=0 &implies; e(E)=3. OPEN: [E_via_D(3), E_via_B(4)].

Key Takeaway
Even though goal node E_via_B was generated earlier in Step 2 with cost 4, A* did not stop! Because the goal test is executed at expansion, the algorithm prioritized node C (e=3), which ultimately discovered the cheaper route through D (e=3), guaranteeing total path optimality.

7Summary & Tricky Practice Questions

High-yield mastery check for quizzes and midterms

Lecture 8 Core Formulas & Properties

  • Algorithm A: Uses f(n) = g(n) + h(n). The g(n) depth factor forces search back to shallower paths if a branch is unproductive.
  • Admissibility: h(n) ≤ h*(n). Guarantees A* returns the optimal minimal-cost path.
  • Monotonicity (Consistency): h(ni) - h(nj) ≤ c(ni, nj) and h(Goal) = 0. Monotonicity &implies; admissibility.
  • Closed List Optimization: Under monotonic heuristics, a state selected from OPEN has already achieved its optimal path; CLOSED nodes never need reopening!
  • Informedness: If h2(n) ≥ h1(n), h2 dominates h1 and expands fewer or equal states.
High-Yield Exam Practice Questions
Question 1 (Tricky): What happens to A* if h(n) is NOT admissible (i.e., it overestimates the cost for some nodes)?

Answer: If h(n) overestimates the true remaining cost, A* loses its guarantee of optimality. It may prematurely return a suboptimal solution path because the true optimal path was assigned an inflated, artificially high f-value and left unexpanded on the OPEN list.

Question 2 (Conceptual): Can an admissible heuristic ever fail to be monotonic? Give an example.

Answer: Yes. A heuristic can be globally admissible (h ≤ h*) everywhere, but fail local monotonicity. For example, consider Start o A o Goal. Step costs are 1. True minimal cost from Start is 2 (h*(Start)=2), and from A is 1 (h*(A)=1). If we assign h(Start) = 2 and h(A) = 0, both are le h* (admissible). However, h(Start) - h(A) = 2 - 0 = 2 > c(Start, A) = 1. The difference exceeds the step cost, violating monotonicity!

Question 3 (Critical Thinking): If h2 dominates h1, does A* with h2 always run in less total execution time than A* with h1?

Answer: Not necessarily. A* with h2 is guaranteed to expand fewer or equal nodes, but if computing h2(n) per state requires extensive CPU calculations, the total wall-clock execution time could be slower than using a simpler, slightly less informed heuristic h1.

Question 4 (Proof Review): Explain why Breadth-First Search is technically an A* algorithm, and state its dominance relationship with other heuristics.

Answer: BFS is Algorithm A with h(n) = 0. Since actual remaining cost h*(n) ≥ 0, 0 ≤ h*(n) always holds, making BFS an admissible A* search. Because any non-negative admissible heuristic satisfies h(n) ≥ 0, every admissible heuristic dominates BFS (h0 le hadm le h*). Hence, BFS expands an upper-bound superset of nodes compared to any informed A* algorithm.

Question 2: Inconsistent Heuristics & The Reopening Visited Nodes Trap

CS401 NUCES Proof Problem

Problem Statement: A student implements A* graph search with an error: "When the algorithm visits a node n that has already been expanded (is in CLOSED), it immediately skips n without checking if the new path to n has a lower path cost g(n)."

  1. What is the effect of this bug on the completeness and optimality of A*?
  2. Under what condition on the heuristic function does this buggy implementation still guarantee optimal solutions?
Model Solution & Theoretical Proof

1. Effects on Completeness & Optimality:

  • Completeness: PRESERVED. The search graph is finite and the algorithm will still explore alternative paths and terminate.
  • Optimality: DESTROYED (Suboptimal Paths May Be Returned!). If the heuristic is only admissible but NOT consistent, the first path discovered to a node n may not be the cheapest. If a cheaper path to n is found later, skipping n prevents A* from updating n's descendants, causing A* to return a suboptimal path to the goal.

2. Under what condition is the buggy algorithm guaranteed optimal?

Answer: When the heuristic function is CONSISTENT (MONOTONIC).

Proof: By the theorem of Monotonic Heuristics, if h(n) satisfies the triangle inequality h(n) ≤ c(n, a, n') + h(n') for all edges, then along any path the values of f(n) are non-decreasing. This mathematically guarantees that:

The first time any node n is selected and popped from OPEN, its path cost g(n) is already guaranteed to be optimal!

Because no cheaper path to n can ever be discovered later, a consistent heuristic ensures that CLOSED nodes never need to be reopened! Thus, under a consistent heuristic, the student's buggy code behaves identically to optimal A*!

FAST Mid-1 Exam Pro-Tips for A* Search

  1. Always Show g, h, and f explicitly: When drawing tree nodes, write g + h = f clearly (e.g. 10 + 3 = 13). FAST exam keys assign 1 mark for g(n), 1 mark for h(n), and 1 mark for f(n).
  2. Do Not Stop When Goal is Placed on OPEN: Never stop search when the goal is added to the frontier! A cheaper path may still be on OPEN. You only declare success when the goal node is popped/extracted from the priority queue.
  3. Tie-Breaking Rule: Follow the specified tie-breaker strictly (e.g., smaller x first, then smaller y). A single tie-breaking mistake flips the expansion order and costs multiple marks across subsequent rows of your trace table.
