1Conceptual Essentials & High-Frequency Traps

Foundations: Agents, PEAS, State Spaces, and Graph Theory (Lectures 1–3)

Trap 1 • Rationality vs. Omniscience

Is a rational agent necessarily omniscient or always successful?

The Trap: Many students write that a rational agent always achieves the optimal real-world outcome or knows everything in advance.

Exam-Grade Answer: No! Omniscience means knowing the actual outcome of actions and possessing complete future knowledge, which is impossible in partially observable or stochastic environments. Rationality is about maximizing expected performance based on the percept sequence received so far and built-in knowledge. A rational agent can make a completely sound decision that still ends in failure due to unforeseen external events.

Trap 2 • State Space Size vs. Search Tree Size

Why is the size of a search tree fundamentally different from the size of a state space?

Exam-Grade Answer: A state space counts only distinct, unique physical configurations of the world (e.g., 5,478 legal reachable Tic-Tac-Toe boards, or 9!/2 = 181,440 8-puzzle states). A search tree represents paths of exploration; multiple nodes in a search tree can correspond to the exact same physical state reached through different sequences of moves. Consequently, a finite cyclic state space can produce an infinite search tree unless cycle-checking (such as Luger's DE or CLOSED set) is enforced!

Trap 3 • Königsberg Bridges & Graph Reachability

State Euler's theorem on Eulerian paths and explain why the Seven Bridges of Königsberg problem has no solution.

Exam-Grade Answer: An Eulerian path (a path that traverses every edge of a graph exactly once) exists if and only if the graph has either 0 or exactly 2 vertices with an odd degree (odd number of incident edges). In the Königsberg bridge graph, all 4 landmasses (vertices) have an odd number of bridges connected to them: degrees 3, 3, 3, and 5! Because there are 4 odd vertices, no continuous tour across every bridge is mathematically possible.

Trap 4 • Goal-Driven vs. Data-Driven Direction

Under what conditions is Goal-Driven (Backward) search vastly superior to Data-Driven (Forward) search?

Exam-Grade Answer: Goal-driven search is superior when:

  1. The goal is specific and clearly formulated, but there is an overwhelming amount of starting data (most of which is completely irrelevant).
  2. The backward branching factor (bbackward) is strictly smaller than the forward branching factor (bforward). (e.g., Luger's ancestor problem: bforward ≈ 3 children vs bbackward = 2 biological parents).

2Uninformed Search & Uniform Cost Search (UCS) Lab

Worked traces and critical algorithmic rules (Lectures 4–6)

Trap 5 • The Goal Test Timing Rule

Explain with a counterexample why applying the goal test at node GENERATION in UCS ruins optimality.

Exam-Grade Answer: If the goal test is performed when a node is generated, the search terminates as soon as any path generates the goal. However, that first path might be deep or expensive!

Concrete Counterexample: Consider Start S, intermediate node A, and Goal G. Edge costs: c(S, G) = 10, c(S, A) = 1, c(A, G) = 2.

  • Expanding S generates G with cost 10 and A with cost 1.
  • If goal test is applied at generation, the algorithm sees G, terminates immediately, and outputs path S → G with cost 10.
  • However, the true optimal path is S → A → G with cost 1 + 2 = 3!
  • By delaying the goal test until a node is popped for expansion, UCS expands A first (cost 1), discovers the path to G with cost 3, and correctly outputs the optimal path!
Trap 6 • Strict Positive Step Costs

Why must step costs in UCS satisfy c(s, a, s′) ≥ ε > 0?

Exam-Grade Answer: If edge costs could be zero (ε = 0) or negative, the search space could contain infinite sequences of actions with zero cost increase. The priority queue would continuously expand zero-cost nodes forever, causing UCS to become incomplete and never reach a goal with positive cost. Requiring ε > 0 guarantees that path costs strictly increase with depth, ensuring the algorithm systematically explores cost contours outward until C* is reached.

3A*, Admissibility & Consistency Proofs Lab

Rigorous proofs and theoretical properties (Lectures 7–8)

Trap 7 • The Admissibility Contradiction Proof

Reproduce the formal contradiction proof that A* is admissible (finds the optimal path).

Step-by-Step Proof:

  1. Assume A* selects suboptimal goal G2 where g(G2) > C*. Since h(G2) = 0, f(G2) = g(G2) > C*.
  2. Let n be an unexpanded node on the optimal path to true optimal goal G.
  3. Since n is on an optimal path, g(n) = g*(n).
  4. Because h is admissible (h(n) ≤ h*(n)):
    f(n) = g(n) + h(n) ≤ g*(n) + h*(n) = C*
  5. Combining: f(n) ≤ C* < f(G2), which implies f(n) < f(G2).
  6. Since A* always pops the node with the lowest f-value, node n must be popped before G2 could ever be selected. Contradiction! A* must terminate with the optimal path. ■ (Q.E.D.)
Trap 8 • Why Monotonicity Eliminates Closed-Node Reopening

Explain mathematically why an A* algorithm with a monotonic heuristic never needs to reopen a node on CLOSED.

Exam-Grade Answer: A heuristic is monotonic if h(ni) ≤ c(ni, nj) + h(nj). Adding g(ni) to both sides:

g(ni) + h(ni) ≤ g(ni) + c(ni, nj) + h(nj)
Since g(nj) = g(ni) + c(ni, nj):
f(ni) ≤ f(nj)
This proves that f(n) values are monotonically non-decreasing along any path. When A* selects a node n from OPEN, its f-value is the global minimum on the frontier. Consequently, no future path can ever reach node n with a strictly lower cost! The first time node n is expanded, its optimal path is already locked in, meaning nodes on CLOSED can be dropped immediately without reopening.

Trap 9 • Admissibility vs. Monotonicity Counterexample

Can a heuristic be admissible but NOT monotonic? Provide a concrete numerical example.

Exam-Grade Answer: Yes. Every monotonic heuristic is admissible, but not every admissible heuristic is monotonic!

Numerical Counterexample: Consider path A → (cost 1) → B → (cost 1) → Goal.

  • True optimal distances: h*(A) = 2, h*(B) = 1, h*(Goal) = 0.
  • Define heuristic: h(A) = 2, h(B) = 0, h(Goal) = 0.
  • Admissibility Check: h(A) = 2 ≤ 2 (valid), h(B) = 0 ≤ 1 (valid). The heuristic is strictly admissible!
  • Monotonicity Check: h(A) - h(B) = 2 - 0 = 2. However, c(A, B) = 1. Here h(A) - h(B) > c(A, B), which violates the triangle inequality!

5Adversarial Search: Minimax & Alpha-Beta Lab

Tree pruning walkthroughs and bound tracking (Lectures 9–10)

Trap 10 • Bound Update Roles in Alpha-Beta

Which bound is updated at a MAX node, and which at a MIN node? What are their initial values?

Exam-Grade Answer:

  • At a MAX node: α is updated (α = max(α, child_val)). α represents the lower bound on MAX's payoff, initialized to −∞, and can only increase.
  • At a MIN node: β is updated (β = min(β, childval)). β represents the upper bound on MIN's payoff, initialized to +∞, and can only decrease.
  • Pruning Condition: Prune whenever alpha ge β (or β ≤ α).

Complete Worked Alpha-Beta Pruning Tree Problem

Consider a 2-ply game tree: Root is MAX with two children A (MIN) and B (MIN).

  • Node A has leaf children: L1 = 3, L2 = 5.
  • Node B has leaf children: L3 = 2, L4 = 9, L5 = 1.

Step-by-Step Execution:

  1. Start at Root (MAX): α = −∞, β = +∞. Calls child A.
  2. At A (MIN): inherits α = −∞, β = +∞. Inspects L1 = 3.
    β = min(+∞, 3) = 3
  3. Inspects L2 = 5. β = min(3, 5) = 3. Child A finishes with value 3.
  4. Back up to Root (MAX): Root updates α = max(−∞, 3) = 3. Now Root has α = 3, β = +∞.
  5. Calls child B (MIN): inherits α = 3, β = +∞.
  6. At B (MIN): inspects first child L3 = 2.
    β = min(+∞, 2) = 2
  7. Check Cutoff Condition: Is alpha ge β?
    3 ≥ 2 &implies; TRUE! (Cutoff Triggered)
  8. PRUNING: Prune remaining children of B (L4 and L5)! They are never evaluated!
  9. Root selects move A with guaranteed optimal score 3.

6Comprehensive Cheat Sheet & Formula Matrix

Quick-reference summary across all 9 lectures

Uninformed Search Formulations

  • BFS: Queue; Complete; Optimal for uniform costs; Time O(bd), Space O(bd).
  • DFS: Stack; Incomplete; Non-optimal; Time O(bm), Space O(b · m).
  • IDS: Iterative stack; Complete; Optimal; Time O(bd), Space O(b · d). Overhead factor ≈ b / (b - 1).
  • UCS: Priority queue by g(n); Complete & optimal for c ≥ ε > 0; Time & Space O(b1 + ⌊C* / ε⌋).

Informed Search Formulations

  • Evaluation Function: f(n) = g(n) + h(n).
  • Admissibility: h(n) ≤ h*(n) and h(Goal) = 0. Guarantees A* optimality.
  • Monotonicity (Consistency): h(ni) - h(nj) ≤ c(ni, nj). Guarantees closed nodes never reopen.
  • Dominance: h2(n) ≥ h1(n) &implies; Nodes(A*2) ⊆ Nodes(A*1).

Adversarial Search Formulations

  • Zero-Sum: Utility(MAX) + Utility(MIN) = 0.
  • Minimax Complexity: Time O(bm), Space O(b · m).
  • Alpha-Beta Optimal Ordering: Time O(bm/2) = O((√b)m), effectively doubling search depth.
  • Pruning Check: Prune whenever β ≤ α.

Luger's Special Lists & Definitions

  • Backtrack Lists: SL (active path), NSL (unexpanded candidates), CS (current state), DE (dead ends).
  • Cycle Elimination: Discard node c if c ∈ SL ∪ NSL ∪ DE.
  • Tic-Tac-Toe Heuristic: E(n) = M(n) - O(n).

The Top 5 Deadly Exam Traps (Tested Repeatedly)

Trap 1: The "Early Goal Checking" Trap in UCS and A* (Fall 2016, Spring 2018)

The Trap: Testing for the goal state when a node is generated (inserted into the frontier) rather than when it is expanded (popped from the queue).

The Reality: In BFS with unit costs, testing early preserves optimality because depth = cost. In UCS and A*, edge costs vary; a deeper path can have a strictly lower total cost! Testing early in UCS or A* destroys optimality and causes the algorithm to return expensive suboptimal paths!

Trap 2: Manhattan Distance Admissibility with Diagonal Steps (Spring 2026 Q1)

The Trap: Assuming Manhattan distance h(n) = |dx| + |dy| is always admissible on 2D grids.

The Reality: If diagonal movement is permitted (e.g. diagonal cost = 4, while two orthogonal steps cost 3+3 = 6), Manhattan assumes two orthogonal moves and predicts 6. Since 6 > 4, Manhattan overestimates diagonal shortcuts and is INADMISSIBLE! The correct admissible heuristic is 4 × min(dx, dy) + 3 × |dx - dy|.

Trap 3: Consistency vs Admissibility & Reopening Visited Nodes (Spring 2018 Q1, Fall 2018 Q1)

The Trap: Confusing admissibility with monotonicity/consistency.

The Reality: Admissibility (h(n) ≤ h*(n)) guarantees optimality for Tree Search. For Graph Search with a CLOSED list, if the heuristic is only admissible but not consistent, a cheaper path to a closed node can be found later! If closed nodes are not reopened, A* will return a suboptimal path. Consistency (h(n) ≤ c(n,a,n') + h(n')) is strictly required to guarantee optimality without reopening CLOSED nodes.

Trap 4: Normal Play vs Misere Play in Take-Away Games (Spring 2026 vs Spring 2025)

The Trap: Skimming the victory condition of combinatorial games.

The Reality: In Spring 2026 (Five-Stone Game), the player who takes the last stone WINS (Normal play: optimal move is take 2 stones). In Spring 2025 (Subtraction Game N=5), the player who takes the last stone LOSES (Misere play). A single misread word flips terminal node values from +1 to -1 across the entire tree!

Trap 5: Alphabetical Tie-Breaking in DFS vs BFS (Fall 2016 Q1, Spring 2024 Q1)

The Trap: Forgetting how LIFO stacks process alphabetical ties.

The Reality: When exam instructions state "Ties are broken alphabetically": In BFS (Queue), push A then B, so A is dequeued first. In DFS (Stack), pushing A then B causes B to sit on top of the stack and be popped first! To expand A first in DFS, successors must be pushed in reverse alphabetical order [B, A]!
