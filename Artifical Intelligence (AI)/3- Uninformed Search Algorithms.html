Uninformed Search Algorithms

1Direction of Search & Branching Factor

Choosing where to begin our graph traversal: Forward vs Backward

When searching through a state space, a fundamental architectural decision is where to begin: starting at the given facts and moving forward, or starting at the desired goal and moving backward. In AI literature (Luger Chapter 3.2), these two directions are known as Data-Driven (Forward Chaining) and Goal-Driven (Backward Chaining) search.

Dimension Data-Driven Search (Forward Chaining) Goal-Driven Search (Backward Chaining)
Starting Point Begins with given problem facts and initial state. Begins with the goal we wish to prove or achieve.
Transition Mechanism Applies rules/actions forward to produce new states until a goal condition is met. Determines what sub-conditions must be true to reach the goal, recursively forming subgoals until facts are hit.
Best Used When
  • All or most problem data is given at the start.
  • There are a massive number of potential goals, but few initial facts.
  • It is difficult to formulate a specific goal description.
  • A specific, clearly formulated goal is given.
  • There is an overwhelming quantity of initial data, most of which is completely irrelevant to the goal.
  • Problem-solving involves diagnostic explanation.

Branching Factor & Search Efficiency

The choice of search direction drastically impacts the total number of states generated. The primary mathematical determinant is the Branching Factor (b)—the average number of children generated by a node.

Luger's Ancestor Search Example (Luger Chapter 3.2 & Lecture 4)

Suppose we want to determine whether "Fred is an ancestor of Me":

  • Direction 1: Data-Driven (Fred → Descendants): Average human couple has roughly 3 children. Thus, the branching factor forward is b ≈ 3. Searching down 5 generations generates:
    3 + 32 + 33 + 34 + 35 = 3 + 9 + 27 + 81 + 243 = 363 descendants!
  • Direction 2: Goal-Driven (Me → Ancestors): Every human being has exactly 2 biological parents. The branching factor backward is strictly b = 2! Searching back 5 generations generates:
    2 + 22 + 23 + 24 + 25 = 2 + 4 + 8 + 16 + 32 = 62 ancestors!

Conclusion: Always choose the search direction that exhibits the smaller average branching factor!

2Luger's Backtracking Search Algorithm

Systematic graph search with loop prevention and failure recovery

Backtracking Search is the foundational systematic search algorithm in AI (Luger Chapter 3.2.2). It begins at the start state and pursues a path down the tree until it either reaches a goal or a dead end. If it hits a dead end, it backtracks to the most recent parent node that has unexamined siblings and tries a different branch.

The Four Tracking Lists (Luger Section 3.2.2)

  • SL (State List): Lists the states in the current active path being tried from the root. If a goal is found, SL contains the complete solution path in reverse order!
  • NSL (New State List): Contains nodes awaiting evaluation (the search frontier/fringe). These are candidate states whose descendants have not been explored yet.
  • CS (Current State): The specific node currently being evaluated (always the most recently added state to SL).
  • DE (Dead Ends): Lists states whose descendants have completely failed to contain a goal. Prevents the algorithm from ever retrying known useless paths.
Cycle Prevention Rule in Luger's Backtrack
Before adding any newly generated child node c to NSL, the algorithm checks:
Is c ∈ SL  or  c ∈ NSL  or  c ∈ DE?
If c is present in any of these lists, it is immediately discarded. This guarantees that the algorithm will never loop infinitely in cyclic graphs!

Worked Backtracking Trace Run (Luger Figure 3.12)

Consider starting at A, where A has children B, C; B has children E, F; E has children H, I (leaves); C has Goal G.

Iteration CS (Current) SL (Active Path) NSL (Pending Frontier) DE (Dead Ends) Action
0 A [A] [A] [] Initial state.
1 B [B, A] [B, C, A] [] Expand A → add B, C to NSL. Select B.
2 E [E, B, A] [E, F, B, C, A] [] Expand B → add E, F. Select E.
3 H [H, E, B, A] [H, I, E, F, B, C, A] [] Expand E → add H, I. Select H.
4 I [I, E, B, A] [I, E, F, B, C, A] [H] H has no children! Add H to DE; backtrack to I.
5 F [F, B, A] [F, B, C, A] [E, I, H] I is dead end! Backtrack: E is exhausted, add E to DE. Select F.
6 C [C, A] [C, A] [B, F, E, I, H] F has no children! B is exhausted. Backtrack to C!
7 G [G, C, A] [G, C, A] [B, F, E, I, H] Expand C → generate G. Goal test succeeds! Return Path: A → C → G.

3BFS vs. DFS Analysis

Queue vs Stack, memory explosion, and structural trade-offs

Breadth-First Search (BFS) and Depth-First Search (DFS) represent the two canonical extremes of uninformed graph exploration:

Property Breadth-First Search (BFS) Depth-First Search (DFS)
Frontier Data Structure Queue (FIFO): First-In, First-Out. Children are appended to the back; shallowest node is popped from front. Stack (LIFO): Last-In, First-Out. Children are pushed to the front/top; deepest node is popped first.
Exploration Order Level by level: explores all nodes at depth k before any node at depth k+1. Deepest path first: plunges straight down a branch until it hits a leaf or cutoff, then backtracks.
Completeness Complete: Guaranteed to find a solution if one exists (provided branching factor b is finite). Incomplete: On infinite graphs or graphs with cycles (without cycle checking), it can get trapped in an infinite branch and never return.
Optimality Optimal for uniform step costs: Always finds the shallowest goal (fewest edges). Non-optimal: Can return a deep, convoluted path even if a 1-step solution exists on an unexamined shallow branch.
Time Complexity O(bd), where d is depth of the shallowest goal. O(bm), where m is the maximum depth of the state space. (If m >> d (i.e., m is much greater than d), time is drastically worse).
Space Complexity O(bd) (Exponential): Must store all frontier nodes at the current level simultaneously. O(b · m) (Linear): Only needs to store the active path and unexpanded siblings along that path. Highly memory efficient!
The Memory Bottleneck of BFS (Exponential Explosion)
In AI search, memory is the fatal bottleneck for BFS, not time!
Suppose branching factor b = 10, nodes generated at 100,000 nodes/sec, and each node requires 1,000 bytes:
  • Depth 2: 110 nodes → 0.11 MB → 1 millisecond.
  • Depth 6: 1.1 × 106 nodes → 1.1 GB → 11 seconds.
  • Depth 10: 1.1 × 1010 nodes → 11 Terabytes of RAM → 1.3 days!
  • Depth 12: 1.1 × 1012 nodes → 1 Petabyte of RAM → 130 days!
BFS exhausts available machine memory long before it runs out of CPU time.

4Depth-Limited Search & Iterative Deepening (IDS)

Achieving BFS completeness and optimality with DFS linear memory

We desire the optimality and shallowest-path guarantee of BFS, but cannot afford its exponential memory consumption. Conversely, DFS uses minimal memory (O(b · m)) but is incomplete and non-optimal.

Iterative Deepening Search (IDS / DFS-ID) provides the optimal marriage of both algorithms (Luger Chapter 3.2.4 & Lecture 5).

Depth-Limited Search (DLS)

DLS is simply DFS with a predefined maximum depth limit l. Nodes at depth l are treated as if they have no successors. This eliminates the infinite loop failure of DFS, but introduces incompleteness if the shallowest goal happens to lie at depth d > l.

How Iterative Deepening Operates

  1. Run DLS with depth limit l = 0. If goal found, return success.
  2. Run DLS with depth limit l = 1. If goal found, return success.
  3. Run DLS with depth limit l = 2. If goal found, return success.
  4. Repeatedly increase l by 1 until a goal is discovered.
The Re-expansion Paradox: Doesn't IDS Waste Time?
Students instinctively believe that restarting the search from the root at every iteration wastes enormous amounts of time.

The Mathematical Reality: In an exponential tree with branching factor b, the vast majority of nodes reside at the bottom level!

  • Nodes at bottom level d are generated 1 time.
  • Nodes at level d-1 are generated 2 times.
  • Nodes at root level 1 are generated d times.
Total Nodes in IDS = d(b) + (d-1)b2 + (d-2)b3 + dots + 1(bd) ≈ O(bd)

When b = 10 and d = 5:

BFS Nodes = 1 + 10 + 100 + 1,000 + 10,000 + 100,000 = 111,111
IDS Nodes = 5(10) + 4(100) + 3(1,000) + 2(10,000) + 1(100,000) = 123,450
The overhead is only ≈ 11%! For this negligible computational price, IDS provides BFS completeness and optimality while requiring only O(b · d) linear memory!

5Uniform Cost Search (UCS) Deep-Dive

Optimal search across non-uniform edge weights • FAST-NUCES Lecture 6

BFS guarantees optimal paths only when all step costs are equal (e.g., each move costs 1). In real-world networks (road travel, airline routes, packet routing), different actions have radically different costs.

Uniform Cost Search (UCS) (also known as Dijkstra's Algorithm in graph theory) expands nodes in order of their cumulative path cost g(n) rather than their depth.

Definition • Uniform Cost Search (Lecture 6 Slide 2)
Instead of expanding the shallowest node, Uniform Cost Search expands the unexpanded node n with the lowest path cost g(n).
  • Implementation: The search frontier is maintained as a Priority Queue ordered by cumulative cost g(n) from the start state.
  • Equivalence: If all step costs are identical, UCS behaves identically to Breadth-First Search.

The Golden Rule of UCS: Goal Test Timing (Lecture 6 Slide 2 & 7)

CRITICAL: In Uniform Cost Search, the Goal Test MUST be applied to a node ONLY WHEN IT IS SELECTED FOR EXPANSION, NEVER WHEN IT IS FIRST GENERATED!

Why? When a goal node is first generated as a child, there could still exist an unexpanded path on the frontier with a much lower cost that eventually loops around to reach the goal with a lower total cost!

Testing for goal at expansion guarantees that whenever UCS selects node n for expansion, the optimal minimal-cost path to n has already been discovered.

The Step Cost Condition: ε > 0

For UCS to be complete and optimal, every legal action must have a cost of at least some positive constant:

c(s, a, s′) ≥ ε > 0
If zero-cost edges or negative costs were permitted, the algorithm could enter an infinite zero-cost loop without making progress toward the goal.

Complexity of UCS

  • Worst-case Time & Space Complexity:
    O(b1 + ⌊C* / ε⌋)
    where C* is the cost of the optimal solution, and ε is the strictly positive minimum step cost.
  • When all costs are equal (ε = 1), ⌊C* / ε⌋ = d, yielding standard BFS complexity O(bd+1).

Worked Romanian Map Walkthrough (Lecture 6 Slide 4)

Finding route from Sibiu to Bucharest:

  1. Start at Sibiu (g=0). Successors are Rimnicu Vilcea (g=80) and Fagaras (g=99).
  2. Priority Queue: [Rimnicu Vilcea (80), Fagaras (99)]. Lowest cost is Rimnicu Vilcea.
  3. Expand Rimnicu Vilcea: generates Pitesti with cost 80 + 97 = 177. Queue: [Fagaras (99), Pitesti (177)].
  4. Lowest cost is now Fagaras (g=99). Expand Fagaras: generates Bucharest (Goal) with cost 99 + 211 = 310.
  5. Notice: Goal Bucharest has been generated with cost 310, but UCS does NOT stop! Bucharest is placed on the priority queue. Queue: [Pitesti (177), Bucharest_via_Fagaras (310)].
  6. Pitesti has a lower cost (177 < 310)! Expand Pitesti: generates a second path to Bucharest with cost 177 + 101 = 278!
  7. Queue: [Bucharest_via_Pitesti (278), Bucharest_via_Fagaras (310)].
  8. Next popped node is Bucharest_via_Pitesti (g=278). Goal test succeeds!

Result: UCS returns optimal path Sibiu → Rimnicu Vilcea → Pitesti → Bucharest (Cost: 278), correctly rejecting the premature path through Fagaras (Cost: 310)!

High-Yield Exam Practice Questions
Question 1 (Tricky): Why will UCS fail to be complete if edge costs can be zero (c(s, a, s') = 0)?

Answer: If zero-cost edges exist, the algorithm can wander through an infinite chain or cycle of zero-cost actions without ever accumulating path cost. Because the priority queue continuously expands zero-cost nodes (g=0), it will never advance to expand nodes with positive cost that actually lead to the goal.

Question 2 (Conceptual): What is the difference between the condition for BFS optimality versus UCS optimality?

Answer: BFS is optimal only when all step costs are equal (c=1), because it minimizes the number of edges (depth). UCS is optimal for general, variable positive step costs because it minimizes cumulative path cost g(n).

Question 3 (Critical Thinking): In UCS, suppose node B is on the frontier with cost 10, and a newly generated path reaches B with cost 7. What should the algorithm do?

Answer: The algorithm must update node B's cost on the priority queue to 7 and redirect B's parent pointer to the new, cheaper incoming path. Because B has not been expanded yet, its previous path is discarded in favor of the cheaper route.

Question 4 (Luger Backtracking): In Luger's Backtrack, if an algorithm reaches a dead end, which list records this failure, and what happens to the State List (SL)?

Answer: The state is added to the DE (Dead Ends) list so that it will never be retried. The state is popped off the top of SL, restoring SL to represent the previous ancestor path before the failed decision was taken.

★FAST Mid-1 Exam Solved Questions (2016–2026)

Authentic Sessional-I Questions on Early Goal Testing, Uniform Cost Search & Algorithm Comparisons

Why This Topic is the Highest Scoring Section on Mid-1

Every single FAST Mid-1 exam tests uninformed search mechanisms. Specifically, the "Early Goal Checking Trap" (checking goal when a node is added to the frontier vs when it is popped) is the single most celebrated question in FAST exam history (appearing in Fall 2016, Spring 2018, and Fall 2018). Master this proof and you are guaranteed 10+ marks!

FAST Mid-I • Fall 2016 & Spring 2018 Question 2 (10 Marks) • Hall of Fame

Question 1: The "Early Goal Checking" Trap in Graph Search

Appeared in 3 Mids Classic FAST Problem

Problem Statement: In standard Graph Search, the goal test is applied when a node is popped/expanded from the priority queue. A student suggests modifying the algorithm by testing whether a node reaches the goal state as soon as it is generated (inserted into the fringe) to terminate faster.

  1. If using EARLY-GOAL-CHECKING-GRAPH-SEARCH with Uniform Cost Search (UCS), is the algorithm still Complete? Justify.
  2. Will it return an Optimal solution? Justify with a concrete counterexample.
  3. Why does BFS remain optimal with Early Goal Checking on unit costs, whereas UCS completely fails?
Complete Mathematical & Algorithmic Proof

1. Completeness: TRUE.

Testing for the goal early upon generation only causes the algorithm to terminate earlier than standard UCS. Since standard UCS is complete on finite state spaces with step costs c ≥ ε > 0, early goal checking will still find a goal state if one exists and terminate. Hence, it remains complete.

2. Optimality: FALSE (LOSES OPTIMALITY!).

Early goal checking completely destroys the optimality guarantee of UCS. Below is the canonical counterexample graph:

[ S ] (Start) / c=10/ c=1 v v [ G ]<------[ A ] (Goal) c=2

Step-by-step Trace under Early Goal Checking UCS:

  • Start at S: Expand S. Generate its successors: G (with cost g=10) and A (with cost g=1).
  • Early Goal Check on Generation: The algorithm tests G as soon as G is generated. Since G is a goal state, the algorithm immediately terminates and returns path S → G with cost 10!
  • The True Optimal Path: The path S → A → G has cost 1 + 2 = 3!
  • Conclusion: The algorithm returned a suboptimal solution (cost 10 instead of 3). Standard UCS would have kept G on the priority queue and expanded A first (since g(A)=1 < g(G)=10), discovering the cheaper route of cost 3.

3. Why BFS is Optimal with Early Goal Check but UCS Fails:

In BFS, all edge costs are uniform (c = 1). Therefore, cumulative path cost is strictly proportional to depth d (g(n) = d). The first time the goal state is generated at depth d, no shallower path to the goal can ever exist. In UCS, edge costs vary arbitrarily: a path with more edges (deeper) can have a strictly lower total cost than a path with fewer edges. Therefore, UCS must delay the goal test until a node is popped from the queue, which guarantees that all paths with lower cost have already been explored.

FAST Mid-I • Fall 2017 Problem 2a (4 Points)

Question 2: In What Ways is Iterative Deepening Better than DFS?

CS401 Sessional 4-Criteria Evaluation

Problem Statement: Provide a rigorous comparison between Iterative Deepening Search (IDS) and Depth-First Search (DFS) evaluated strictly against the four standard criteria used to compare search algorithms.

Model Solution
Criterion Depth-First Search (DFS) Iterative Deepening Search (IDS) Why IDS is Strictly Superior
Completeness Incomplete (can get trapped in infinite paths or cycles in infinite state spaces). Complete (guaranteed to find goal if branching factor b is finite). IDS systematically increments depth limit (0, 1, 2, ...), so it can never be trapped down an infinite branch.
Time Complexity O(bm), where m is the maximum tree depth (m can be ∞). O(bd), where d is the shallowest goal depth. When m >> d (e.g. goal at depth 5, but tree extends to depth 100), DFS wastes exponential time in deep dead ends, while IDS finishes at depth d.
Space Complexity O(b × m) linear space. O(b × d) linear space. Because d ≤ m, IDS uses strictly less or equal memory than DFS!
Optimality Not optimal (returns the first path found down the leftmost branch, regardless of length). Optimal (for unit step costs). IDS guarantees finding the shallowest goal state first, ensuring shortest path.

Summary Conclusion: IDS combines the optimal completeness of BFS with the modest linear space complexity of DFS. It dominates DFS in all four fundamental criteria.

Question 3: BFS vs DFS Graph Search Traces with Alphabetical Tie-Breaking

Standard Trace Problem Step-by-Step Table

Problem Statement: Consider a search graph with start node S and goal node G. Successors are always broken alphabetically (e.g. A before B). Contrast the expansion sequence and path returned between Breadth-First Graph Search (FIFO queue) and Depth-First Graph Search (LIFO stack) when avoiding repeated states (Closed list).

Model Solution & Frontier Dynamics
[ S ] / [ A ] [ B ] / [ C ] [ D ] [ G ] | [ G ]

1. Breadth-First Graph Search (Queue: FIFO):

  • Expand S → Fringe: [A, B]
  • Expand A → Fringe: [B, C, D]
  • Expand B → Fringe: [C, D, G]
  • Expand C → Fringe: [D, G] (G already in fringe)
  • Expand D → Fringe: [G]
  • Expand G → GOAL FOUND! Path returned: S → B → G (length = 2 moves).

2. Depth-First Graph Search (Stack: LIFO):

  • Expand S → Push successors in reverse alphabetical order so A is on top: Stack: [B, A]
  • Pop A → Successors C, D. Stack: [B, D, C]
  • Pop C → Successors G. Stack: [B, D, G]
  • Pop G → GOAL FOUND! Path returned: S → A → C → G (length = 3 moves, suboptimal!).

FAST Mid-1 Exam Pro-Tips for Uninformed Search

  1. The Golden Rule of UCS: In UCS, Goal Test MUST be applied when a node is popped from the priority queue, NEVER when it is generated/inserted! If you write that UCS tests goals upon insertion, you will lose 5–10 marks immediately.
  2. Zero-Cost and Negative-Cost Edges: UCS requires all edge costs c ≥ ε > 0. If zero-cost edges exist, UCS can loop infinitely. If negative-cost edges exist, Dijkstra/UCS fails completely (requires Bellman-Ford).
  3. Tie-Breaking Order: FAST exams almost always specify: "Ties are broken alphabetically". Double check whether successors are inserted into a stack or queue, as stack (LIFO) requires pushing in reverse alphabetical order to expand alphabetical first!
